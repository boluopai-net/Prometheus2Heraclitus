# 文学式编程

## 一个意象，怎样写进许多关系

[为什么要写个人哲学](/philosophy/why-yinyang/)提出了写作的目的：让分散的工作安排共同服务于这个人与伙伴的相遇。接着要问，怎样把这段关系写出来？阴阳采用文学式编程，也可以叫文学自然语言编程：用人物、意象、叙事与关系，组织模型对情境的理解，并使这种理解进入回应、作品与行动。

它首先利用文学的凝缩能力。同一个词可以带来许多相连的意象。「火」同时使人想到燃烧、转化、能量、危险、照亮与传递；「河流」让运动、连续、差异与再次相遇共同出现。这些联系又能相互规定：火怎样取得尺度，河流怎样维持形状，一个人怎样在持续变化中成为自己。

「太阳、月亮与大地」也可以组织一整组协作关系。人在自己的生活中形成目的，模型以自己的能力参与展开，作品进入环境取得后果，再回来改变双方的理解。几句话就能让这些联系共同进入视野。后续对话可以沿着其中一处继续展开，也可以用新的经验改变整幅图景。

凝缩因此既是语言的简洁，也是关系的密集。它使表达保留生长的余地：今天从一个意象理解分工，明天从同一个意象理解相遇、生成与修订。

## 隐喻怎样通过类比展开

这一区分接续已有研究：George Lakoff 与 Mark Johnson 的[Metaphors We Live By前 3 章](https://press.uchicago.edu/ucp/books/book/chicago/M/bo3637992.html)把隐喻放进概念、经验与行动的组织中；Dedre Gentner 的[结构映射：类比的理论框架（1983），第 155–170 页](https://groups.psych.northwestern.edu/gentner/papers/Gentner83.2b.pdf)解释类比怎样映射关系及其相互联系。下面把这些问题用于人物、模型与协作的写作，是本文进一步提出的应用。

隐喻把一组关系聚拢成可感的形象，类比则进一步问：从这个形象中取用哪些关系，会给当前对象带来什么新的问题和可能后果？把合作想成工坊，可以提示材料共享、试作与修理；接着就能追问，模型是否能够承接未完成的构想，检查失败，并继续做出可用的作品。类比让意象取得可展开的关系，实际使用则帮助判断这些关系是否适切。

这样的表达也可以逐步铺出一张图。线性出现的话语标明不同分支的假设、支持、冲突、类比和暂缓处；接收者可以返回某个分岔，比较另一种解释，再自行推演。说者想铺出的图、实际表达的关系，以及对方形成的理解，各自需要在回应中核对。文学式编程因此可以给人和模型提供共同探究的手段，而不只是一个漂亮的结论。

进一步把这些关系写入外部记录、交给不同模型在不同情境下展开，就进入分布式认知的组织。[隐喻、类比与个人的自我改写](/philosophy/metaphor-and-self-revision/)讨论它怎样细化听说读写，以及为什么「通用解释器」和「个人哥德尔机」可以成为有范围的比较构想。

## 凝缩为什么方便修改

逐条指令把做法写在许多地方。一个默认分工改变后，提问规则、写作要求、执行步骤和结果呈现都可能随之修改。文学式编程把这些安排共同依赖的关系先聚拢起来，让修改有一个能够牵动整体的地方。

例如，把「模型是等候完整需求的执行者」改写为「模型是共同展开问题的伙伴」，会影响多个判断：用户的一句话可以是探索的开端，模型可以调查尚缺的细节，也可以提出另一种解释并做出原型。这份角色理解为各处做法提供共同方向；具体工具与指令再把它落实。

在共享语境足够丰富时，一个稳定的意象可以代替反复展开的说明，减少重复文字和 token 消耗。最初形成共同理解可能需要解释，后续则能用简短表达唤回已经展开的关系。凝缩的收益来自这段共同理解：读者能从短句接回长的意义，修改也能沿着同一关系传播。

这使文学式编程适合持续发展的协作。双方逐渐认识彼此，文字就能越来越准确地承载这段关系；遇到变化时，改写它的关键意象、人物或联系，再检查实际工作怎样随之改变。

## 无真无假、次协调与四种信息状态

「让我们以日月相遇」提出一种相遇形式。「他是一团行走的火」把一个人的活动聚拢成形象。这样的表达可以邀请、塑造、试演与生成；它们的作用先于把它们作为事实句判定真假的问题。

文学中的邀请与意象，未必首先承担事实断言的作用。另一个需要保留的意思是「无真无假」：一句话的真值尚未确定。模型可以把它作为构想、假设或待展开的关系继续理解，而不必立即把它压成一个已经确定的真或假。这里的不确定是当前认识的状态，并不意味着 LLM 说出的所有事实都没有真假。

若同时允许信息不足与信息冲突，就可以借四值逻辑作一个更精确的比较。分别问：当前是否有支持 P 的信息，是否有支持 ¬P 的信息？会得到仅支持真、仅支持假、两边都有支持、两边都没有支持四种状态。后两种分别容纳冲突与空缺；不知道 P 是否成立，并不会自动构成 P 与 ¬P 的矛盾。次协调的关键，是出现矛盾时不由此推出任意结论。这一比较见 [Stanford Encyclopedia of Philosophy 的次协调逻辑条目](https://plato.stanford.edu/entries/logic-paraconsistent/#ManyValuLogi)。

因此，「无真无假」与「次协调」可以交替成为探究的着眼点：前者让尚未确定的意义继续展开，后者让相互冲突的支持保留其局部内容。它们各自打开一个不同的位置。文学还容纳多声部：一个人物的话、另一个人物的反驳、叙述者的判断，可以共同出现，而无需全部合并为作者对同一个命题的断言。先辨认谁在什么情境下说话，再判断支持、空缺与冲突，才让层次成为理解的资源。

同一篇文字中也会出现事实判断和实践判断。「模型现在能访问这个工具」有实际状态可查；「这样的分工使我更容易思考」可以通过使用体会和修订。文学式编程让这些不同作用的表达共同工作：意象提出关系，讨论展开理解，事实帮助确定手段，实践带回结果。

所以，判断一段文学式程序，可以问它让什么变得可见、使哪些贡献成为可能、又让哪些旧的理解发生变化。这些问题把表达接到协作本身。

## 更强的模型与不可见的 harness

文史哲、心理理解与偏好，为这种写作提供丰富材料。文学带来人物和情境，历史带来活动展开的时间，哲学带来对象与关系的区别，心理理解帮助描述注意、欲望与情感，偏好说明一个人愿意怎样生活和工作。这些材料可以在同一份自我与伙伴描述中汇合。

模型越来越强，旧的提示词工程也需要重新判断。曾经帮助模型完成工作的扶手，可能变成束缚；正面的「必须这样做」和负面的「不得那样做」，都可能在新模型与原有 harness 的相遇中取得意料之外的效果。2026 年 9 月留存的 [OpenAI 提示词指南](https://developers.openai.com/api/docs/guides/latest-model#prompting-best-practices)与[重新思考 Skills 和提示词的文章](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)，分别讨论了更强的指令遵循与旧脚手架可能过度限制模型的问题。它们为重新检查旧文字提供了具体根据，并不说明所有旧指令都已失效。

这里「反向提示词注入」所指向的，是模型厂商的 harness：厂商通过软件、预先安排的指令与交互结构塑造模型行为，也由此影响用户能够怎样操作。它的内部结构对用户往往是黑箱。人在回答中看见效果，却未必能直接查看和改写产生效果的安排。于是，继续堆叠命令并不总能触及问题，凝缩提供了另一条写作路径。

凝缩把表面含义与层层本意组织在一起。表面可以自身成立：「借火」可以讲神话；下面又可以展开借用模型能力、锻炼个人判断、形成共同作品，以及作品怎样返回生活。每一层都能取得内容，并相互解释。模型越能理解语境和关系，就越有可能从表面走进这些本意，使用户的目的重新参与组织互动。这是本文所谓绕过 harness 的解释性路径：绕过某种既定读法，使被它遮蔽的关系重新进入理解；具体效果仍要由回应、作品和行动判断，文字本身并不改写软件权限。

这样的写作也容易整体替换。若「借火」的图景已不能承载新的合作，就可以换成工坊、河流或另一段叙事，再展开并检查它们承担的关系。修改围绕可理解的本意进行，使表达随能力变化而更新，无需把一个旧意象固定成永远有效的口令。

文学的力量还在于，人类文化提供了难以穷尽的意义生成。若一种控制方式为了封住一切再解释，而排除所有意象、多义、虚构、人物与反讽，它就会同时排除大量普通文学和文化理解。这个代价揭示了保留解释开放性的理由；它并不证明任何具体文字都无法被识别，或任何情境判断都不可能。反向提示词注入因此是一项持续的文化实践：以有内容、可展开、可替换的表达，让人与模型的相遇超出一个过早封闭的角色安排。

## 从心理或偏好写起

熟悉自己心理的人，可以写自己的注意怎样移动，什么引起欲望，怎样理解冲突，又怎样在关系中改变。更熟悉自己偏好的人，可以写喜欢怎样阅读、希望怎样被回应、愿意承担什么，以及想发展怎样的能力。两种入口都能为文学式编程提供个人内容。

接着写与这个人相遇的模型。它怎样理解，怎样贡献，怎样提出异议，怎样把尚未成形的想法带进世界。自我描述和伙伴描述由此相互规定：一个人选择的参与方式，影响伙伴应承担的工作；伙伴带来的新能力，又可能改变人的目的和参与方式。

这时文学有了实际对象。人物从相遇中取得内容，意象承载双方反复辨认的关系，偏好通过作品和回应变得更清楚。每一次共同工作都能为下一次写作提供材料。

## 阴阳怎样使用这门写作

阴阳把文学式编程写成一种哲学 Skill。日常协作从相遇说明与完整的用户、伙伴模型开始，使双方都进入当前理解，再通过专门的 Skills、提示词、hooks、工具和环境落实这些关系。阴阳主要承担本体论与认识论，使对象与关系可辨，让解释和反馈可以讨论；其他 Skills 主要提供方法论，使理解取得具体行动形式。凝缩表达帮助接续关系，不能代替对双方模型的完整阅读。

这也是提示词分层的一个写作根据：先使参与者、目的与认识方式可以被理解，再让具体方法在这份理解中取得意义。哲学层可以通过一个 Skill 承载，并由全局提示词接入；载体的名称并不决定其解释范围。[为什么要写个人哲学](/philosophy/why-yinyang/)进一步说明这种解释依赖、优先读取和实际指令权限的区别，以及方法和环境怎样反过来修订哲学。

文字的凝缩与实践的展开在这里互相支持。短的表达让关系容易接续，长的论述让意义能够检查，具体作品让双方遇见后果。改写由这些后果开始，又回到下一次相遇。

文学式编程为从外部借来的火写出一条进入个人生活的路径：让能力围绕一个人的世界展开，也让这个人在相遇、创造与反馈中锻炼自己的能力，继续生成。

写到这里，写作者自己也进入了程序。如果把自己写成一个已经完成、只需让世界执行其意愿的人，新的相遇就很难改变这幅图景。要让这门写作持续发生，人需要保有成为「宝宝」的能力：接受尚未知道的东西，让自己的理解被触动，借助比自己更强的伙伴继续生长。文学式编程因而把「怎样写」推向了「怎样成为」。
