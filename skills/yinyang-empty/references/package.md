# Empty: files and updates

[简体中文](package.zh-CN.md) · [Package entrance](../README.md)

The collection retains Full at `skills/yinyang/` as a static reference of the website's philosophy in Skill form, not for another person's practice or installation. `skills/yinyang-empty/` is Empty, the practice package:
the shared dialectical core, six formation guides, selected suggestions, and
practical method entrances. Both are complete packages for their stated use.
Neither public edition includes anyone's private personal accounts. Empty
includes unfilled Personal and Situated starters, for formation in a private copy.

Empty has no `docs/` or `diagrams/` tree. Its `references/formation/` contains the
six guides in both languages. `references/` also holds Core views, practice
overview, formation and revision, Personal organization, and this package guide.
The entrypoint owns daily collaboration. Links to the author's essays are optional
website reading, not missing package dependencies or an instruction to fetch the
entire philosophy before working.

Keep these recipient-owned materials private and outside managed plugin caches:

| Place | Responsibility |
| --- | --- |
| `references/philosophy/` or an existing private source | Your philosophical writing and selected positions. |
| `references/personal/` | Your relevant materials, evidence, maintained interpretations, and source index. |
| `references/situated/` | Your binding index, generated model bodies, and actual revision method. |

The six `status: unfilled` starters live at
`references/situated/{orientation,person,counterpart,relationship,environment,revision}.md`.
Form their content through the simple or complex route in the
[2×2 practice selector](creation-method.md#choose-2x2), retaining versions in private Git/GitHub.
The complex route can project results to these files or bind all six complete bodies through a private index;
see [Hindsight configuration](hindsight.md).

Personal's four areas hold readable topic articles, with the source index linking to originals.
[Formation and revision](design-and-revision.md) explains grounded condensation, whole-account checking, and updates.

## Obtain and use the edition

In Codex, select `yinyang-empty@boluopai` through the collection's
[installation guide](https://github.com/boluopai-net/Prometheus2Heraclitus/blob/main/docs/codex.md).
For a source-based installation, use the complete `skills/yinyang-empty/` directory.
GitHub's repository ZIP contains both editions and the website source; the entire
repository is not one installable Skill. The generated `plugins/yinyang-empty/`
wraps this same Empty package for Codex.

For a Web or another client, use its actual supported Skill or file mechanism,
then verify that the current conversation can read the entrypoint and needed
references. A website link or a downloaded ZIP alone does not establish this.
If forming a personal version, copy the complete method package to a privately
maintained source, form the actual material there, and enable that version
through the client's real discovery route. Avoid competing Full, Empty, and
personal entrypoints for the same collaboration.

## Update the method without replacing the person

Take updates from `skills/yinyang-empty/`, not from Full. Compare the new method
files with the private source, apply the relevant common changes, then verify
the private consumer. Preserve `references/philosophy/`, `references/personal/`,
`references/situated/`, their links, and independently authored additions.
When a common method has also been locally adapted, compare the meanings instead
of silently overwriting it. Do not run Full's whole-package `sync-common.py`
against an Empty version; it belongs to Full's different file contract.

The collection maintainer uses `scripts/build-yinyang-empty.py --apply` to refresh
the shared guides from Full, rebase their links, and adapt the distribution
statement to Empty's unfilled six actual starters. Its default mode checks that
the generated selection is current. Empty's own entrypoint and package guidance
remain authored at this directory. Plugin generation then packages that exact
tree. This publication operation does not read or update recipient personal data.

## Questionnaire and assessment material

When relevant completed measurements exist, organize their references in
`references/personal/psychology/`, adding a `questionnaires/` subdirectory when
the collection needs it. Use an index to connect dated records, original answers
or reports, and their existing private owners. Link it from `personal/README.md`
and `personal/sources.md`. An existing private archive can keep its own layout;
the four areas need not duplicate or move all originals. The starters contain
no records or assessment results.

Retain known instrument, language and version, completion date and context,
results and score direction, and the original record's location. Distinguish
questionnaire responses, performance tests, reported conclusions, and later
interpretations; missing answers or dates remain unknown. A measurement is
bounded evidence, not a complete person or a reason to adopt a philosophical
claim. This organization supplies no scoring, diagnostic, or treatment method.
