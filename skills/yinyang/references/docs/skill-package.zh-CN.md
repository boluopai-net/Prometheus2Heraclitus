# 共享 Skill 与个人哲学

[首页](../../README.zh-CN.md) · [阴阳方法](../../SKILL.zh-CN.md) · [English](skill-package.md)

**Prometheus2Heraclitus**是 Skill 集。其中的阴阳形成 Skill 位于
[`SKILL.md`](../../SKILL.md)，其 `references/` 中有
[形成与修订阴阳](../design-and-revision.zh-CN.md)、
[在实际环境中实现阴阳](../harness-adaptation.zh-CN.md)和
[按问题阅读](../reading-map.zh-CN.md)。`references/` 内的 `docs/` 与 `diagrams/` 是同一完整包中的阴阳配件。
集合根目录本身不是阴阳 Skill。

共享 Skill 提供可以采用和改写的能力与材料，个人哲学则由自己的经验、问题、
来源与实践形成。阴阳是其中一种已经展开的例子；读者可以从它开始，也可以
结合其他思想，形成有不同名称、概念和组织方式的作品。

**哲学可改，个人内容必须重建。**可以保留五份核心文件的结构，同时替换上层哲学：
填入自己的思想，或有依据地建模一位哲学家的思想作为框架。哲学、意象与论述服务于
实际的人与伙伴关系的建模；无论选哪套哲学，五份文件都要描述真实使用者及其协作。
哲学家的思想模型不能顶替使用者的个人模型。自行改写的哲学保留在自己的维护版本中，
不使用公共文件更新器覆盖；公共内容字节一致的约定只适用于选择持续跟随本仓库公共版本的副本。

下面以目前维护的阴阳实现说明一种具体做法。[从这个例子开始，写出自己的东西](example-and-commons.zh-CN.md)
解释更广的邀请：直接采用、组合，或独立改写它的哲学与形式。下面的技术路径
服务于这一种实现，不是普遍的文学格式。另行创作的作品在自己的维护位置
保持源内容与引用连贯；下文的公共文件更新器不用于那个作品。

公开网站提供阅读与文件浏览，完整 Skill 从公开 GitHub 仓库取得。
可以直接克隆仓库，或下载仓库 ZIP 后保留所需包的完整目录。
阴阳原创材料采用 CC BY-NC-SA 4.0，其他四个独立 Skill 保留 MIT 许可；
使用和分享遵循各材料已有的许可与署名要求，参见[集合说明](../../../../README.zh-CN.md)。

取得完整的 `skills/yinyang/`，通过实际使用环境的 Skill 机制让模型读取。
这会提供形成方法，不会直接建立个人关系。使用模型读过入口，检查获授权的实际环境
和相关心理建模或偏好材料，再帮助使用者把个人哲学及具体关系写入其私人维护位置。
之后，在当前任务授权内，把有依据的理解落实到环境并核验结果。

沿用这一种实现的分发包与个人包具有相同结构和字节一致的公共内容。公共主入口 `SKILL.md`
承载目的与阅读路径；直接对话的主模型在实质工作前，随它完整读取[相遇](../encounter.md)、[用户模型](../models.md)、[伙伴模型](../relationship.md)、[实际使用](../usage.md)及[来源索引](../sources.md)。Codex 与私人 Web ChatGPT 都适用，当前上下文中已有的完整有效文本可以复用。
五个固定情境槽位在两种包中保持相同的名称与作用：

**采用这套实现时，下列五份都必须从形成指引改写为自己的实际内容，
并整理 `references/personal/` 中相应的私人材料。**这是形成个人版的必要工作，
不是可略过的装饰性定制。模型负责根据授权材料完成写作；用户不必亲自维护这些文件。
尚未明确的关系可以如实保留为未知，不必先取得完整自传或完整心理理论。

| 槽位 | 个人包中的内容 |
| --- | --- |
| `references/encounter.md` | 能够直接用于协作的实际相遇的凝练描述。 |
| `references/models.md` | 展开的用户模型。 |
| `references/relationship.md` | 模型伙伴及双方关系。 |
| `references/usage.md` | 在实际环境中的用法与协作分工。 |
| `references/sources.md` | 来源所有者与私人出处的总索引。 |

这些文件在分发包中承载形成指引，在个人包中由使用模型写入有依据的实际描述。
形式化的用户描述也属于个人信息，不因采用某种记号就成为公共内容。
[设计参考](../design-and-revision.zh-CN.md)说明形成与修订。不能复制作者画像或虚构替代画像。
已有个人哲学采用这个实现时保留有依据的内容，不用通用指引覆盖它。

[私人配套材料](../personal/README.md)属于 `references/personal/`。
这些页面记录出处与未公开的私人材料。哲学正文即使由本人创作，也只维护一份；
私人对应页链接正文，说明实际来源与隐私边界，不再另写一套「个人应用」。
有有用来源时才建立对应页，不必为每篇文章创建空页。
文件名根据这个人的证据自然变化，不由此形成不同的包结构。
私人内容不提交回共享集合。

完成时检查五份文件是否已经彼此连贯地描述实际的人、伙伴、关系与环境，
`personal/` 的必要材料和出处是否可取得，以及实际对话模型能否从使用入口读到并使用它们。
只下载文件、保留五份通用指引或复制他人画像，都没有完成个人版。
初次形成后，随实际协作修订有变化的部分；不要求每次更新都重写全部文件。

其余材料都是公共内容：文档、图示、`design-and-revision.md`、
`harness-adaptation.md`、`reading-map.md`、包管理文件、README 与 OpenAI YAML 适配文件。
共享 GitHub 包是公共内容的权威维护位置。`scripts/sync-common.py` 默认检查投影，
`--apply` 把公共源内容投影到目标，同时保留五个槽位及 `references/personal/` 内的一切。
原生维护者把投影源落实到本地与私人 Web 使用环境。这个过程不导出个人内容，
不是服务或自动个人上传。后续公共修改因此保持共享，不分叉成不同的本地与分发指令。

用明确的包目录运行源内容比较：

```bash
python3 /path/to/shared/yinyang/scripts/sync-common.py \
  --source /path/to/shared/yinyang --target /path/to/situated/yinyang
```

加上 `--apply` 复制有变化的公共文件，再运行一次比较。新的个人包从完整共享副本开始，
然后填写个人文件。目标中未对应的文件或公共路径中的符号链接会使命令在复制前停止；
应检查它们的归属，不静默删除。命令只更新源包，运行时安装与云端发布仍通过当前环境已有维护者完成。

`references/docs/` 中的论述解释形成过程所用的思想，彼此关系见首页。
它们不是额外的 Skill，也不是线性安装步骤。虚构 mini 包或计算器不能代替个人形成
与实际环境改造。
