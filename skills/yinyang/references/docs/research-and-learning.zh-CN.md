# 科研与学习

**大部分时候关注全局与整体，少部分时候深入熟悉重点与细节，并知道什么时候应当检验它们。**学习先把握一个领域的问题、概念与关系，形成整体感，再按需要深入局部。优先学「最泛」的东西，也就是能够跨具体任务使用的理解和方法。

设计就是一个例子：判断要做什么、为什么做、怎样组织整体，以及什么结果才算合适。AI 承担实现后，人可以把主要学习精力放在这些问题上。设计两次甚至多次，是提出和比较不同方案，必要时重新考虑问题、前提和评价标准。更进一步，连组织实践与反思的框架本身也可以改变；这就是这里所说的[在当前双环之外推理](https://boluopai.net/philosophy/embodied-experimental-philosophy/)。

## 1. 从兴趣草拟课程体系

### 探索兴趣，比较培养方案

从一个感兴趣的方向开始，例如「人因」。和 AI 聊聊自己更想理解人的认知、人与机器的配合，还是产品和工作环境的设计，用具体问题逐渐明确方向。

让 AI 搜索国内哪些学校在相关方向上比较有积累，查找**近几年的硕士培养方案和相应招生专业的考研参考书目**。人因相关内容也可能以工效学、工程心理学、人机交互等名称出现，应结合实际研究团队和课程判断。提取课程、主要内容、先修要求与书籍，保留学校、院系、年份和原始链接。

如果不同学校分别偏工程、心理或设计，或者设在计算机、心理、人工智能、设计等不同院系，就选几份有代表性的方案，让 AI 解释它们各自关注什么问题、重视哪些知识与方法。

### 以一个方案为主，草拟课程体系

让 AI 根据你感兴趣的问题、对课程的反应和想做的事情，判断哪个方案最适合，并说明理由，供你选择或修正。**以最感兴趣的方案为主，用其他方案查漏补缺**：合并重复课程，补足基础与方法，安排先修顺序，区分核心课和按兴趣深入的课。先得到一套可调整的课程体系草案，每门课都能说明为什么学、与其他课有什么联系。

这时先有方向和课程草案。接下来取得材料、准备工具时，逐步记录哪些课程、书籍和实际能力能够相连，待它们落实后再整理成学习路径。准备中若发现课程不合兴趣、资料不合适或工具条件改变，可以返回换课、调整课程体系，甚至换一个更感兴趣的方向。

## 2. 把课程与书籍变成可读材料

### 找到对应资源，下载整理

拿着课程体系，主要寻找**主题或课名对应的国外网课，并选择最新的可获得版本**。核对课程大纲和授课年份；名称不同但内容相近时说明对应关系，只有旧版时注明版本。国内考研参考书，以及培养方案或课程材料提到的书籍，也可以一起寻找。

让模型下载找到的全部可获取资源，包括视频、讲义、课件、字幕、作业、代码和书籍，按课程整理并检查完整性。模型无法完成的下载，列出材料、原始链接和原因，由本人手动补齐。目录中标明哪些已下载、哪些只有在线入口、哪些仍待补齐。

### 让模型准备相互连接的笔记

把课程体系和资料交给 **Dot 或本地 Codex**，让它使用 **Teacher Skill** 写学习笔记：按课程解释概念与关系，配上术语表、例子和必要图示，保留原始章节、讲次或页码，并给出清楚的阅读入口。笔记要说明对象是什么、为什么这样理解，并连接正在读的材料、已有理解、兴趣与实际问题；没有科研计划，也可以围绕一本书或想做的作品学习。

对于持续学习的一门课、一本书或一个主题，可以采用下面的材料安排。它们服务于同一个学习对象，不按视频、课件和每份参考资料重复建立一套：

| 学习材料 | 数学与技术学习：三份相连的材料 | 哲学阅读：两份相连的材料 |
| --- | --- | --- |
| 术语表 | 独立保存概念、符号、条件和重要区别，以概念图显示关系，便于随时查回。 | 独立解释术语在作者、时代与论证中的含义，并用概念图连接它们。 |
| 主指南 | 学习与研究指南：展开知识结构、原理、推导、例子、阅读顺序，以及与自己的问题有关的联系。 | 阅读指南：展开问题、主张、理由、异议与回应，保留解释分歧及相关联系。 |
| 习题与实验 | 分清书面习题与实验／制作部分；问题、解答和评价依据便于分别阅读，练习与指南、术语互相连接。 | 不自动加一套技术实验。讨论、解释、比较和反例可以在阅读中展开；确实选择了技术活动，再准备相应训练。 |

这就是三份与两份的区别，并不是每本书都要额外写五个文件。总的理论与实践路径负责跨课程的选择；一本书的指南负责这本书的理解，不再复制一份总路径。原文与模型解释也保留各自身份。

需要训练材料时，可以先按课程整体范围准备题目、解答与评估依据，核对答案并把题目和解答分开保存。这样以后有材料可选，不要求现在就全部练习。这里先备好资料、笔记和训练材料，实际阅读与练习放在环境和学习路径落实之后。

## 3. 准备实践工具与环境

材料与笔记准备好以后，让模型根据课程草案、已取得的资料和想发展的能力，把真正要用的环境接起来。软件可以先安装备用，也可以由模型辅助操作；不必因为界面复杂、暂时不会用就排除。是否安装、是否付费、是否能够使用，以及是否已经熟悉，是不同的判断。

| 需要准备的部分 | 对学习的作用 |
| --- | --- |
| 软件与素材 | 用来绘图、原型、音视频、三维、统计或实验；准备可打开的文件、素材与保存位置。 |
| 软件插件与资源 | 补充导入导出、组件、图表、动画或特定操作，检查它与当前软件版本是否配合。 |
| Skills 与教学方法 | 让模型知道怎样协助这类工作，怎样解释、制作和核对。 |
| MCP 与账号连接 | 让模型实际访问所需文档、设计文件、数据或软件操作；连接后要做一次真实读取或修改。 |
| CLI、脚本与界面操作 | 根据软件实际能力选择命令行、程序接口或电脑界面，让模型把操作完成。没有 MCP 的软件也可以通过其他可用方式工作。 |

不用每项工具都配齐以上全部入口。先让模型查现有软件、插件与公开接口，选择能完成当前事情的组合，再用一个小的实际操作验证：能否读取材料、完成操作、保存结果、重新打开并继续。安装成功或显示「已连接」，还不是整条实践路径已经可用。

使用付费工具时，先了解许可、订阅与功能限制；准备软件不等于同意购买。需要固定版本时，记录可用版本，关闭相应自动更新，并保留可恢复的安装材料。版本选择服务于实际兼容性与使用，不必追逐每一次更新。

把准备中确认的工具能力、可用材料与操作入口留给下一步编写路径。开始实践以后，再把「这个工具适合做什么」「我怎样表达要求」「怎样判断结果」「还想熟悉什么」补回实践路径。软件清单和安装记录可以由模型维护，给人阅读的入口则应说明可做的事情、与课程的关系和如何开始。模型读取的协作描述与个人材料可以支持这种安排，但不替代人能读懂的学习路径，也不需要公开个人记录。

## 4. 写出理论与实践学习路径

材料和实践环境已经准备好后，让模型把准备中逐步形成的对应关系整理成两条可用的路径。理论路径应指向实际取得的课程、书籍、笔记与章节；实践路径应指向实际可用的工具、素材、操作入口，以及要发展的能力。准备前的课程草案提供方向，这一步才有充分依据把两条路径写具体。

**理论路径按知识组织，实践路径按能力与工具组织。**同一门课通常既有理论也有实践，但两种组织方式回答不同的问题。课程能帮助理解概念、原理和方法；只有读课，还不足以形成设计、分析或制作的能力。实践遇到的困难又会指出哪些理论值得回去深学，不必等课程全部读完才开始。

| 路径 | 组织什么 | 怎样使用 |
| --- | --- | --- |
| 理论学习路径 | 领域问题、课程模块、概念关系、先修知识与阅读材料 | 建立整体理解，按问题选择深入的课程与章节。 |
| 实践学习路径 | 表达与判断、工具使用、制作或实验、结果检查与修订等能力 | 从当前想熟悉的能力进入，结合实际对象练习，再返回相关理论。 |

实践路径写成**能力与工具大纲**，不要用一个预先编造的项目代替整个方向。例如设计可以区分纸上草图、视觉表达、信息与交互结构、原型、动效、平台差异和设计交付；统计可以区分数据整理、图表、模型选择、解释与复核。它们是能力范围，具体用什么作品、数据或任务来练习，留给实际学习时选择。

如果目的是就业，让模型查阅真实岗位要求与工作材料，区分共同基础、专项分支、资历条件和可选工具；如果目的是兴趣、创作或研究，则根据相应的作品、问题和方法选择。不能从一份招聘、一个软件清单或模型的想象推导出所有人都要完成的训练。

原有课程适合时可以保留，只补上实践路径及其与课程的对应关系。路径帮助选择与接续，不必变成每天的固定配额。核对两条路径能否带到相应材料和可用环境；缺口回到前面的准备环节补齐，随后再开始阅读与实践。实际学习中的新兴趣和困难，也可以使路径及准备工作重新调整。

## 5. 阅读、实践与重点检验

完成材料、环境和路径准备后，再进入实际学习。准备阶段由模型整理和核对资料、测试工具，不要求本人提前开展下面的课程阅读或练习。**都准备好以后，心情好、想学的时候再打开。**

<a id="learning"></a>

### 选择一个方便使用的老师

| 老师 | 使用侧重 |
| --- | --- |
| [本地老师（Local Teacher）](https://github.com/boluopai-net/Prometheus2Heraclitus/tree/main/skills/local-teacher) | 在本地 Codex 中读教材与论文、复习，也能结合文件、代码和实验边学边做。 |
| [云端老师（Web Teacher）](https://github.com/boluopai-net/Prometheus2Heraclitus/tree/main/skills/web-teacher) | 在 Web 对话中探究问题、比较理解、探索相邻知识，并组织课程材料与学习接续。 |

两者共享教学方法，可以从当前方便的入口开始。直接说「带我读这篇论文」「解释这个概念与我原来理解的关系」或「帮我讨论这个研究想法」即可。老师也可以调用下面的学科资料与科研方法；下载、安装、连接和具体选用交给模型。通用工具与文件安排见[工具使用](https://boluopai.net/getting-started/)。

### 从眼前的问题读起

打开主指南，先看这一单元要理解什么、与前后有什么关系；术语陌生时，沿链接查术语表，再回到当前段落。需要确认原意、推导或证据时，再打开标出的原文位置。指南不只是原文目录，术语表也不要求先背完才能阅读。

用图示看见关系，用讨论说出自己的理解与疑问；让老师连接新旧知识、比较解释，展开尚未说清的部分，再检查它有没有理解错。不必每次都中断阅读，把所有细节彻底学完。保存的笔记和当前讲解可以互相修订：有用的例子、解释与新问题写回原来的材料，而不是不断增加难以找回的副本。

### 理论理解与实践熟悉并行

理论学习沿着问题、概念与理由展开；实践则选择大纲中一个有用的能力，用实际材料、工具和反馈使它变得可辨认、可操作。读过动效原理，可以观察并比较转场，再制作和修改一段响应；理解统计模型，可以用真实或明确标注的教学数据，检查输入、输出和解释是否对应。实际任务可以不断更换，不必让整条学习路径依附于一个项目。

熟悉工具既包括知道它能做什么、文件与操作如何组织，也包括判断何时用它、怎样表达意图、怎样检查结果。模型可以承担复杂界面的操作、代码和重复制作；人可以通过纸上草图、照片、口述、比较和修订参与。若想培养自己的手绘或直接操作能力，就保留相应的亲手尝试；若岗位或考试要求本人操作，也要按那个要求检验。不要把模型完成的部分直接算成自己的独立掌握。

### 什么时候需要检验重点与细节

当一个细节可能改变整体判断、结果与预期不符、理解出现矛盾，或准备把方法用到新情境时，就回到相关概念、条件与证据。先和老师判断究竟卡在哪里，再用例子、反例、推演或实验检查。例如，从相关关系走向因果解释时，需要弄清多加了什么假设，以及证据是否支持它。

**实际练习应删去预备材料中的大部分，只留下当前真正必要的极少数关键点。**对这些点，增加图示、具体例子和小步练习，必要时反复做、换情境再检验，直到足以支持眼前的理解与判断，然后返回整体。未选中的材料仍可保留，遗忘或以后需要时再取用。

练习帮助形成理解；测试提供表现证据；评估则据此决定哪里还需改进。解释、回应反例和实际作品也能提供证据，不必都变成考试。判断个人理解时，要区分自己完成的部分和模型提供的帮助；一次答对或模型产出正确答案，都不能单独证明自己已经掌握。

### 科研还需要检验成果

学习可以为了兴趣和理解世界，不必服务于科研；科研则围绕尚未解决的问题形成可论证、可检验的成果，并在过程中继续学习。**个人理解与研究成果的可靠性要分别判断。**让模型回到原始来源核对引文与主张，检查论证前提、计算和代码，并用不同方法、反例或重现结果交叉核验。人需要看懂关键假设、证据与局限，判断成果是否回答了问题；发现知识缺口时，再回到相应课程。
