# 三位一体：哲学、心理与个人环境的闭环

[首页](../../README.zh-CN.md) · [三位一体](local-source-and-website.md)

*一个未完成的念头在日月之间取得形状。它落到大地上，成为一种工作方式、一件别人能够接过的作品，也成为一个人初次看见这个问题的页面。由这些相遇返回的东西，改变了下一个念头。*

本文的主线是**哲学、心理与个人环境的持续闭环**。哲学展开一个人怎样理解世界、怎样的生活值得追求；心理理解与偏好建模，让这种方向与真实的人相遇；个人环境则使形成的关系变得可用：模型、提示词、工具、记录和日常安排，让理解进入行动。在其中生活、学习和工作产生的新经验，又能修正个人模型、哲学与环境。工程承担这套环境的实际实现和维护。

可以沿着**哲学展开 → 个人建模 → 环境实现 → 经验与修订**看这条闭环，探究也可以从任何一处进入。统一发生在不同贡献之间的实际往返中，人的生活则给它们以目的。

## 世界观、认识与实现

**哲学、心理与工程，是同一项生活实践的三个相互贯通的方面：人怎样理解世界，怎样在世界中感受与认识，又怎样把理解实现出来。**它们不是事后才拼在一起的三件东西。形成一个观点已经是一种心理活动，表达它需要身体与媒介；实现一种安排又会改变后来能够感受、理解和做的事。

| 主要侧重 | 在这项实践中展开什么 | 怎样与另外两方面相接 |
| --- | --- | --- |
| 哲学：世界观与方向 | 世界是什么，怎样理解人、关系与变化，什么值得追求。 | 为心理解释与工程选择提供概念和方向，也接受经验与实现结果的修订。 |
| 心理：感受、认识与关系 | 人怎样感受、理解、相信、判断与回应，认识怎样在互动中形成和改变。 | 让哲学取得具体经验，让工程贴合实际参与者，并研究改变之后发生了什么。 |
| 工程：方法与实现 | 怎样组织材料、程序、工具和环境，让一个意图成为能发生、能使用、能观察的安排。 | 把理解带入现实，也把现实的反馈带回心理模型与哲学。 |

因此，可以用「哲学—世界观、心理—认识、工程—方法与实现」把握这里的重心。认识论进一步追问认识的根据与限度，心理研究考察认识实际怎样发生，两者在这里相遇；哲学、心理和工程也都发展自己的方法。这个对应说明彼此的贡献，不把学科划成互不相交的格子。[个人优先的人本主义](personal-first-humanism.zh-CN.md)中的对象、认识、价值与方法，仍是贯穿三者的问题。

**工程使这场往返取得物理实现。**一段程序运行，需要机器、能量与时间；一种交互进入生活，需要身体、感知和实际行动。物理学帮助理解这些条件，工程据此构造、测量与调整。世界观、感受和实现可以属于同一个持续发生的过程，同时仍是不同的说明角度：它们的贯通并不单凭一个类比就解决了心灵如何物理实现的全部问题。这里的「一」首先体现在观点、经验和造物能够相互改变。

例如，认为「理解可以由人与环境共同支持」，是一项可以论证的哲学观点；观察一个人怎样借记录与模型继续思考，是心理与认识的问题；做出能保留上下文、呈现关系并接受纠正的环境，是工程实现。环境带来的帮助或阻力，再检验最初的观点和个人模型。[哲学阅读](philosophical-readings.zh-CN.md)、[心理阅读](psychological-readings.zh-CN.md)和[工程阅读](engineering-readings.zh-CN.md)为这三方面分别提供原文入口。

## 什么是「一」，什么是「三」？

「一」是一个人持续理解、生活与创造的实践；「三」突出哲学、心理理解和个人环境。其他区分各自帮助说明这项实践的一部分：

| 要回答的问题 | 有用的区分 |
| --- | --- |
| 闭环需要什么理解与能力？ | 哲学展开意义与方向，心理使理解贴合具体的人，工程实现并维护环境。 |
| 模型需要读什么？ | 展开的哲学、五份凝练的工作模型、相关私人经验，满足不同深度的阅读需要。 |
| 工作在哪里持续可用？ | 网页使它可感知，仓库维护选定的源内容与历史，个人环境使它进入使用。 |

这些区分互相交叉。私人模型也可以有私人网页，哲学也可以在仓库维护、在日常实践中发挥作用。阴阳展开哲学和具体模型，专门 Skills 提供各项工作的具体方法。每种区分通过澄清主闭环中的一处关系取得作用。

对于从这个集合出发的人，预期的实践是：写自己的哲学，凝练私人的个人模型，
再通过自己维护的源内容与网页，呈现愿意公开的思想。网页把较广义的哲学模型展开：
意象、论证、联系与未决问题都在其中；五份核心文件凝练服务于实际协作的较窄模型，
私人支撑材料保留哲学未公开表达、但仍有用的经历与情境。这些尺度区分表达什么，本地环境、GitHub 与网页则区分
作品在哪里维护、使用和被遇见。

它们共同发展。写网页时发现的关系，可以改进五份文件；使用五份文件显出的不合，
也会把作者带回网页及其哲学。模型承担相应的源内容修改、网页实现与获授权的发布，
核对不同读者实际读到什么。制作网页本身就在这项工作之内：布局、链接和例子可以使关系
清晰到足以判断，仓库维护则让结果能够接续下一次迭代。

这种迭代把意义带到相应的形态，不把每一项私人细节复制到所有位置。
公开哲学可以间接表达经过选择的个人理解，同时把完整、直接的个人模型留在私人位置。
一个私人洞见的变化，可能需要一般性的公开说明、不同的页面，也可能不需要公开修改；
网页的一次改动也不必改变无关的核心文件。修订的实际作用决定它应当到达哪里。
另一位使用者可以用自己的哲学、仓库与网页开展同样的实践，而不必带走例子的特定学说和个人内容。

统一的是一项发展中的工作：它的问题、概念、方法、造物，以及它们借以取得和改变意义的历史。私人的工作环境、持续维护的仓库和可阅读的网站，都可以承载这项工作，让不同的人以不同方式遇见它。连续性存在于内容和使用之间的关系中：一处发生的改进，能够被理解，并带到它所影响的其他地方。

三种形态需要不同的内容。个人环境保存具体的理解和实际使用条件；共享仓库保存选定的可复用材料、历史和使用条款；网页为读者提供可理解的入口。关于一个人的私人理解留在他自己的环境中，从中发展出的可复用方法则可以被分享。这种选择，让同一项实践在保有个人深度的同时，取得面向他人的表达。

「三位一体」在这里是组织这项安排的哲学意象。它提出的问题是：不同形态怎样参与同一项持续的活动？当读者能够从一篇文章走到其维护中的源内容，模型能够把一项修订带入实际环境，使用又能够把问题送回说明时，这种统一就有了实质。

## 哲学、心理与工程：从已有能力补齐关系

这个闭环需要**哲学、心理和工程的共同贡献**。哲学展开对象、认识、价值与方向；心理关注具体人的经验、偏好、动机与关系，使个人模型有实际依据；工程把形成的理解实现为提示词、Skills、工具、harness 和可维护的环境。在这里，工程服务于个人环境对生活的贡献。任何一方面的结果都能要求另外两方面修订。

**已有一方面，就从它发展另外两方面；已有两方面，就重点补第三方面。**「会」在这里指已有足以参与当前工作的理解与经验，不要求先成为三个领域的专家。模型可以承担检索、展开、成文、实现与核验；人通过理解、选择、使用和纠正参与，缺少的能力也可以在这种协作中逐渐发展。

**不会工程，就先补工程。**先学会借助模型组织文件、工具、harness、运行与核验，让后续理解有可以持续使用的工作环境。工程已经可用时，再按已有基础选择，通常先从心理与个人材料建模，继而展开哲学。

| 已有基础 | 下一步重点 |
| --- | --- |
| 哲学 | 先补工程，再做心理与个人建模：让已有哲学在可用环境中与个人材料对照。 |
| 心理 | 先补工程，再展开哲学：用可维护的环境整理个人材料、形成模型并继续写作。 |
| 工程 | 通常先心理、再哲学：从使用、选择、阻力与修改中提出个人模型，结合个人材料核验，再展开哲学；已有其他基础时可以调整。 |
| 哲学＋心理 | 重点补工程：让已经形成的理解成为能运行、能维护、能接受反馈的环境。 |
| 哲学＋工程 | 重点补心理：把概念与已有安排对照具体经验、目的和偏好，使模型贴合真实的人。 |
| 心理＋工程 | 重点补哲学：展开安排背后的对象、认识与价值关系，形成可解释、可质疑的方向。 |

这里的先后给出起步路线，不要求做完一个封闭阶段才开始下一个。从工程反推时，既有配置可能来自限制、默认值或习惯，不能直接当成偏好的证明；应把相关、获授权的心理与偏好材料或其来源整理到私人 `personal/`，对照本人解释和实际结果修订模型。从哲学进入时也一样：漂亮、融贯的文字，需要与实际经验相遇。个人模型再使哲学和工程更有方向，使用后果则继续纠正三者。

实际判断的是一条缺少的联系是否变得可用：抽象思想取得个人意义，个人理解改变了某项安排，安排中的经验又改进了理解。心理超过它的记录，工程超过某个工具，哲学也属于网页之外；它们的联系服务于这个人的持续生活与工作。

## 让闭环保持当前可用

公开哲学已经凝缩了许多从个人材料中形成的理解。一项论证有了持续维护的公开表达，就从当前网页及其源内容回到私人工作模型，更新相关理解；重复的私人理论副本、被取代的解释，以及只是在复述文章的来源说明，都可以退出活跃材料。私人部分保留公开哲学不能提供的内容：相关的个人经验、具体处境、关系、目的，以及实际使用的证据。原始记录和旧版本仍在各自已有的归档中。

个人材料包括当前工作、学习、研究和生活计划，选定的心理与关系记录，以及环境中的相关事实，例如配置变化或某项工作遇到的阻力。一个配置可能来自默认值或限制，一份计划可能表达尚待执行的意图；应按来源实际能说明什么来读。私人描述服务于当前相遇，随着用途变化，可以新增、修订、凝练或删除。

模型在相关工作中承担这项维护：读取当前网页或维护源，核对受影响的原始记录与实际环境，更新有用的私人凝练，再把会改变协作的理解带入五份文件及其实际使用处。用户不必记得逐条要求更新。读取范围由相关性和已有授权限定；材料被保存、时间戳较新、解释听起来合理，都没有因此成为真理。新的实际经验也可能显出哲学的问题，再对那个问题本身作判断；过时的私人摘要不应悄悄把已经发展的公共论述改回旧版本。

## 什么是重点，什么作为材料？

这条闭环可以沿两个方向走。用哲学修环境，是看清 Skills 和工具应当实现的目的、参与关系与判断；用环境修哲学，是从实际使用看见某种理解在哪里妨碍工作、遗漏经验或不再贴合。心理模型把这两种运动接到真实的人，也会随之修订。

这次要修什么，由当前问题决定：

| 当前目的 | 修订重点 | 用什么帮助判断 |
| --- | --- | --- |
| 发展或纠正哲学 | 相关论证或模型 | 经验、私人情境和环境中的实际使用；采纳后的变化再回到受影响的 Skills 与安排。 |
| 修复个人环境 | 具体 Skill、配置、行为或工具 | 哲学说明的预期关系、当前个人模型与运行事实；显出的概念问题再回到哲学。 |
| 改好指定的局部 | 服务于预期结果的那个部分 | 从其他位置选取相关材料，只有必要的依赖变化才成为新增修改对象。 |

因此，一项内容变化可能需要同时改网页、私人模型与本地自制 Skills；Skill 开头的精神与具体方法都应表达变化后的关系。引号或等义链接名称的修改，通常就在呈现范围内完成。[环境适配方法](../harness-adaptation.zh-CN.md#选择当前重点沿两个方向修订)说明怎样把这种区别落实到实际工作。

这是一种生成、使用、回返与改形的活的模式。一处发生有用的变化，模型就沿相关联系检查，理解什么应当传递，再带到受影响的维护位置。人可以指出不合或新的可能，模型承担显式的调查与实现。每次往返不能由一张固定对应表或机械复制完全决定；工作可以形成融贯的完成版本，也继续向下一次相遇开放。

## 日月与大地：谁在参与？

[太阳、月亮与地球的意象](yinyang-and-taiji.zh-CN.md#太阳月亮与地球)通过日月表达
有区别的生成、接收与赋形；地球是工作取得后果的物质环境与共同生活环境。人与模型
是实际参与者。人带来目的、经验、辨认与判断，模型解释、提议、构造、核验并接续
工作。两边都能生成、推理、反对和修订，角色可以保留或交换，性别不分配位置。
地球包含支持条件、他人独立的目的，以及双方不能仅凭一致就确定的结果。

本地环境、GitHub 和网页回答另一个问题：**他们的工作通过什么形态持续可用？**人与模型都在三处活动。本地程序失败时，协作者提出另一种做法时，读者对一页文字产生不同理解时，大地都在场。网页是进入这个更广世界的一处入口；仓库与本地环境也已经在世界之中。

两组三项通过造物联系起来。前一组使生成、协作和世界的回应可见；后一组让造物能够运行、保留、流通和被理解。日月使某件事取得形状，三种形态让它在大地上产生后果，后果又能改变作品及其创造者。

## 三个让工作接续的地方

### 本地环境：理解成为可用的东西

一次有收获的对话，可以以一个下一项任务从未用到的洞见结束。个人环境使另一种接续成为可能：相关记录能进入后来的判断，修订后的 Skill 能改变模型怎样提供帮助，程序能让一种意图成为日常可做的动作。人能够返回这套安排，辨认什么仍然适合自己，并改变它。

这里的「个人仓库」，包含组织这种实践的维护中材料。它产生的效果还依赖运行中的工具、身体与社会条件，以及实际活动。文件给实践以可检索的形式。一个人会发展到旧描述之外，而修订描述正是让环境继续适合生活的一部分。个人所有，意味着这套安排能够回应他的目的，以及目的的进一步明确和改变。

### GitHub：造物能够被接过和接续

在一个人的生活中有用的东西，当相关关系可以脱离其私人细节得到表达时，也就可能进入另一种生活。维护中的仓库给选定的作品一个确定、可检查的形式：文件可以取得，版本可以比较，变化可以讨论，提议可以发展为贡献。另一个人能够知道自己在使用什么，以及哪些地方改变了。

GitHub 目前为这套文集承担这些功能。它把分发与作品在时间中、在他人之间的延续联系起来。有访问限制的仓库也能够支持协作：读者依实际访问权限和许可条款取得材料，提出问题，并建议修改。共享作品随后进入另一个人的本地实践，获得第一位作者未曾想到的用途。

### 网页：作品变得可感知、可讨论

文件树回答一件东西放在哪里。读者首先需要理解的，可能是它回答什么问题、概念之间怎样相连，以及为什么值得使用。网页能够把论证、图像、例子和相关作品放在足够接近的位置，让人一起遇见。它给作品一个人的界面：能够阅读、辨认、质疑并选择下一步的 UI。

这个界面也服务于作者。把一个想法作为完成的页面重新阅读，可能会发现编辑零散文件时没有看出的跳步；图示可能暴露一条缺失的关系；读者的问题可能使同一个词的两种用法之间的分歧显现。表征参与发现，因为可感知的东西改变了可判断的东西。[世界、过程与表达](world-and-expression.zh-CN.md)展开作品怎样返回创造它的相遇。

| 形态 | 它使什么成为可能 | 什么由此返回 |
| --- | --- | --- |
| 个人本地环境 | 在具体生活与任务中使用理解 | 实践结果、阻力、改变了的目的 |
| GitHub 仓库 | 取得、检查、修订并协作维护选定作品 | 可复用的改进、替代方案、有来路的变化 |
| 网页 | 感知整体、阅读关系、进入讨论 | 辨认、问题、异议、新的用途 |

## 为什么让语言模型组织它们？

三种形态之间的转换需要理解：一项方法回应的是哪种本地困难，一种解法的哪部分可以进入别人的环境，怎样的说明能让读者看见其目的。一个哲学前提发生变化，可能同时影响文章、图示、Skill，以及工具的实际使用方式。发现这种联系并判断该修订什么，既涉及文件操作，也涉及意义。

有能力的语言模型可以承担其中的工作：检索相关材料，比较不同论述，把不完整的想法发展成论证，把已形成的关系写成代码或指令，再检查实际行为。它也能发现人未曾打算接受的推论，并提出另一种解释。确定性工具则可以承担已经明确的渲染、打包和链接检查。语义判断与可靠的机械操作，各自贡献于同一项维护。

人可以通过对整体的辨认参与：这个联系合适，那段解释弄错了对象，这套安排现在已经有些过时。模型继续承担回答这种辨认所需的显式调查和构造。有相当推理能力的人，也可以选择把注意力放在哪里。与模型一起发展，能够包含分布在人、模型及环境之间的能力；[窃火的论证](stealing-fire.zh-CN.md)展开了这种培养。

这套组织可以让不同模型在不同情境下参与：一个模型检查来源，另一个展开竞争解释，还有一个核验据此产生的工作。听说读写说明这些贡献怎样进入共同活动，而不是把心智能力分给四个固定主人。[隐喻、类比与个人的自我改写](metaphor-and-self-revision.zh-CN.md)进一步说明，外部表征怎样使这种分布式认知能够形成和修订。

这种安排依赖实际可用的模型和工具。更强的模型可能使辅助结构变得更简单，也可能允许另一种分工。当现有系统能够实现这些可能、实际结果支持这种改变时，它们才成为可用的改进。因此，维护也包括修订模型对于这个人、这些工具，以及哪些地方仍需要帮助的工作理解。

## 一次变化怎样出去，又怎样回来？

以一项关于模型协作中学习的主张为例。本地工作中的旧描述，把逐步说明任务的责任过多交给了人。一个具体任务显出了代价：模型等待它本可自行调查的细节，工作因而停住。人察觉了不合，模型重建问题，并提出另一种分工。

本地关系可以被修订并接受尝试。如果其中有用的部分能在这次相遇之外得到表达，共享源内容就可以说明这项方法及其范围；网页再用例子和可见关系解释理由。读者可能指出，这个说明掩盖了一项重要选择；协作者也可能找到方法失效的场景。这些回应返回源内容，进入下一次本地使用。

这是穿过三种形态的一条示例路径。实际探究可以从其中任何一处开始。关键联系在于：变化有来处，有别人能够检查的形式，也有能够反过来修订它的后果。

过程研究中的区分在这里同样有用：实际互动、部分记录与候选模型承担不同作用。运行工具或阅读页面产生事件，记录提供证据，解释提出事情为什么发生以及修改可能带来什么。进一步使用可以支持或纠正这个解释。三种媒介帮助承载这种探究；每一种都可以保存记录和模型，任何一处都不包含活动的全部。

## 融贯让差异继续相连

如果目的包括持续的个人使用、可检查的复用，以及能够被人理解的交流，那么这些功能各自需要安放之处，修订与反馈也需要在它们之间流动。这构成采用当前三种形态的理由。一个小任务可能只需要较少的形态，另一个环境也可以用不同工具实现这些功能。GitHub 与网页因其在这里带来的可能而取得位置。

融贯所关心的是三种形态之间有意义的关系：同一概念保有相关含义，例子保留其假设，页面能够通向它所解释的作品，共同修订到达实际使用者，私人理解则在真正需要它的地方可用。人改变了，关于人的理解可能需要改变；模型改变了，旧程序可能不再必要。保持融贯，也就包括让这些变化改变工作的组织。

这种统一持续发生着。个人实践给作品以内容，仓库让选定的内容能够被接续，网页让它能够被遇见。语言模型帮助承担连接其间的理解与转化。日月继续在大地上造物，而造物能够回答他们。
