# 三位一体：哲学、心理与工程的实践闭环

[首页](../../README.zh-CN.md) · [English](local-source-and-website.md)

*一个未完成的念头在日月之间取得形状。它成为一种可以使用的安排、一件能够接续的作品，也成为一个人能够理解的页面。由这些相遇返回的东西，改变了下一个念头。*

**「一」是共同的物理现实，「三」是其中的哲学、心理与工程。**哲学思考、心理活动
和工程实践，都是具有物理实现的活动。三者先在本体上统一，再形成实践中的闭环：
它们发生在同一世界之中，理解并改变这个世界。差别在于各自使什么变得可理解、
又以什么方式工作。当代火一元论把这一现实理解为过程：参与者、他们的模型与安排，
都在其中形成、持续和改变。

## 同一物理现实，不同抽象层次

在这种共同的物理实现之中，哲学阐明对象、关系、认识、价值与方向；心理
研究感受、认识、偏好与互动；工程构造并改变这些活动继续发生的条件。思考一个
环境、体验它、修改它，可以是同一相连物理过程中的不同方面。

这里的**工程本体，是对这个过程中选定部分的计算表达**。人和语言模型共同发展
问题，选取边界、尺度与连续性。事件、状态、持续的对象、关系、约束与转移规则，
说明计算机要表示什么、能够有用地模拟哪些变化。对象与稳定视图作为过程中的
有范围连续保有位置。哲学前提由此进入工程模型的含义，不把工程留给一份脱节的
事物清单。

这份模型在数据、由模型解释的语言、程序、提示词、工具与界面中取得工作载体。
是否适当，取决于实际使用者怎样使用这些区分，以及结果怎样对应观察。模拟考察
模型前提下的后果，实际使用则检验前提及其实现是否服务于目的。共同物理基础既
没有独自给出这些桥接，也没有给出可行计算。
[世界、过程与表达](world-and-expression.zh-CN.md#一个有范围的计算例子模拟冷却实验)通过冷却实验
展开这个过渡，[层次图](../diagrams/layers.zh-CN.html)呈现其中关系。

共同基础连接这些探究，却不使它们的解释可以互换。论证在物理上的发生不能确定
它是否有效；装置能够运行，也不能确定其目的是否值得。回答任何一个问题，
都需要选取相关对象与关系，解释证据怎样支持判断。因此，上层描述承担实质工作：
物理上的统一不能独自选出恰当抽象、建立它与观察之间的桥接关系，或使其计算可行。

## 世界观、认识与实现

| 维护中的材料 | 它承担什么 |
| --- | --- |
| 五份处境文件之外，阴阳的共同哲学 | 过程本体论及其相对于问题的计算表达：对象怎样持续与改变，计算机怎样表示选定关系，实际后果怎样纠正模型；其中的论证也讨论认识与价值。 |
| 相遇、用户模型、伙伴与关系、实际使用、来源这五份文件 | 这次相遇的本体论与认识论：谁在参与、彼此怎样关联，以及形成这份理解所依据的材料、解释、纠正与使用。 |
| `personal/` 支撑材料及其原始来源 | 为哲学与五份文件提供依据：相关经验、目的、表达和环境事实；公共思想来源也支持一般哲学。 |
| 专门的 Skills | 方法论：怎样研究、教学、写作、实现与维护；工具和运行中的安排使这些方法取得实际作用。 |

这些是相连的功能，而非装载不同学科的容器。共同哲学包含认识论，心理探究有其
方法与本体论，工程既需要对象模型，也需要改变对象的程序。本体、认识、价值与
方法所区分的问题贯穿三种贡献：什么存在，如何认识它，什么值得追求，以及怎样
继续，相互影响而不合并为一个问题。[个人优先的人本主义](personal-first-humanism.zh-CN.md)
展开这项实践的价值与方向。

**三者本来就有物理实现，工程有意识地重组其发生条件。**程序需要机器、能量与时间，思考和交互涉及身体、感知与行动。物理学研究物质条件，工程在其中构造、测量与调整安排。哲学与心理的物理基础，并不等到工程加入才出现。

例如，认为「理解可以由人与环境共同支持」，是一项可以论证的哲学观点。调查人和
模型怎样借记录接续问题，涉及心理与认识。双方能够共同建模：什么算相关上下文，
何种变化应当保留或替换它，什么能够表明成功接续。在检索、提示词与工具中实现
这些关系，是工程。使用返回的证据同时检验安排与原先引导它的观点。人和模型
在同一条链中分工：辨认、显式展开、构造与评估相互影响，不要求全部能力都内化到
人身上。双方都能生成和判断，当前模态条件与任务需要塑造各自贡献。
[哲学阅读](philosophical-readings.zh-CN.md)、[心理阅读](psychological-readings.zh-CN.md)和
[工程阅读](engineering-readings.zh-CN.md)为这三方面提供原文入口。

## 哲学、心理与工程：从已有能力补齐关系

这个闭环需要**哲学、心理和工程的共同贡献**：融贯的思想可能没有贴合这个人，
个人描述可能缺少可用环境，运行中的工具也可能追求未经考察的目的。把三者连接
起来，每一方面才有机会显出另外两方面尚未解决的问题。

**已有一方面，就从它发展另外两方面；已有两方面，就重点补第三方面。**「会」在这里指已有足以参与当前工作的理解与经验，不要求先成为三个领域的专家。模型可以承担检索、展开、成文、实现与核验；人通过理解、选择、使用和纠正参与，缺少的能力也可以在这种协作中逐渐发展。

**不会工程，就先补工程。**先学会借助模型组织文件、工具、harness、运行与核验，让后续理解有可以持续使用的工作环境。工程已经可用时，再按已有基础选择，通常先从心理与个人材料建模，继而展开哲学。

| 已有基础 | 下一步重点 |
| --- | --- |
| 哲学 | 先补工程，再做心理与个人建模：让已有哲学在可用环境中与个人材料对照。 |
| 心理 | 先补工程，再展开哲学：用可维护的环境整理个人材料、形成模型并继续写作。 |
| 工程 | 通常先心理、再哲学：从使用、选择、阻力与修改中提出个人模型，结合个人材料核验，再展开哲学；已有其他基础时可以调整。 |
| 哲学＋心理 | 重点补工程：让已经形成的理解成为能运行、能维护、能接受反馈的环境。 |
| 哲学＋工程 | 重点补心理：把概念与已有安排对照具体经验、目的和偏好，使模型贴合真实的人。 |
| 心理＋工程 | 重点补哲学：展开安排背后的对象、认识与价值关系，形成可解释、可质疑的方向。 |

这里的先后给出起步路线，不要求做完一个封闭阶段才开始下一个。从工程反推时，既有配置可能来自限制、默认值或习惯，不能直接当成偏好的证明；应把相关、获授权的心理与偏好材料或其来源整理到私人 `personal/`，对照本人解释和实际结果修订模型。从哲学进入时也一样：漂亮、融贯的文字，需要与实际经验相遇。个人模型再使哲学和工程更有方向，使用后果则继续纠正三者。

擅长工程、暂时解释不出自己心理的人，也可以建模自己的偏好：在实际情境中重视什么、
选择什么、避开什么、又怎样修改。这可以作为协作中可用的心理描述，不要求先解释
内部机制。再据此形成伙伴模型的偏好与优先关系：在这段合作中应注意、维护、质疑
什么，怎样作取舍。这些选定的优先关系说明 agent 应当怎样参与，实际行为再检验
它们能否实现。

实际判断的是一条缺少的联系是否变得可用：抽象思想取得个人意义，个人理解改变了某项安排，安排中的经验又改进了理解。心理超过它的记录，工程超过某个工具，哲学也属于网页之外；它们的联系服务于这个人的持续生活与工作。

## 三个让工作接续的地方

### 本地环境：理解成为可用的东西

一次有收获的对话，可以以一个下一项任务从未用到的洞见结束。个人环境使另一种接续成为可能：相关记录能进入后来的判断，修订后的 Skill 能改变模型怎样提供帮助，程序能让一种意图成为日常可做的动作。人能够返回这套安排，辨认什么仍然适合自己，并改变它。

这里的「个人仓库」，包含组织这种实践的维护中材料。它产生的效果还依赖运行中的工具、身体与社会条件，以及实际活动。文件给实践以可检索的形式。一个人会发展到旧描述之外，而修订描述正是让环境继续适合生活的一部分。个人所有，意味着这套安排能够回应他的目的，以及目的的进一步明确和改变。

### GitHub：造物能够被接过和接续

在一个人的生活中有用的东西，当相关关系可以脱离其私人细节得到表达时，也就可能进入另一种生活。维护中的仓库给选定的作品一个确定、可检查的形式：文件可以取得，版本可以比较，变化可以讨论，提议可以发展为贡献。另一个人能够知道自己在使用什么，以及哪些地方改变了。

GitHub 目前为这套公开文集承担这些功能。读者可以依许可取得作品、提出问题并建议
修改。共享作品随后进入另一个人的本地实践，获得第一位作者未曾想到的用途。

### 网页：作品变得可感知、可讨论

文件树回答一件东西放在哪里。读者首先需要理解的，可能是它回答什么问题、概念之间怎样相连，以及为什么值得使用。网页能够把论证、图像、例子和相关作品放在足够接近的位置，让人一起遇见。它给作品一个人的界面：能够阅读、辨认、质疑并选择下一步的 UI。

这个界面也服务于作者。把一个想法作为完成的页面重新阅读，可能会发现编辑零散文件时没有看出的跳步；图示可能暴露一条缺失的关系；读者的问题可能使同一个词的两种用法之间的分歧显现。表征参与发现，因为可感知的东西改变了可判断的东西。[世界、过程与表达](world-and-expression.zh-CN.md)展开作品怎样返回创造它的相遇。

## 哲学、工作模型与私人材料

对于从这个集合出发的人，预期的实践是：写自己的哲学，凝练私人的个人模型，
再通过自己维护的源内容与网页，呈现愿意公开的思想。网页把较广义的哲学模型展开：
意象、论证、联系与未决问题都在其中；五份核心文件凝练服务于实际协作的较窄模型，
私人支撑材料保留哲学未公开表达、但仍有用的经历与情境。这些尺度区分表达什么，本地环境、GitHub 与网页则区分
作品在哪里维护、使用和被遇见。

写网页时发现的关系，可以改进五份描述；使用这些描述显出的不合，也会把作者带回哲学。
模型承担受影响的源内容修改、实现与获授权的发布，核对不同读者实际读到什么。
一个私人洞见可能需要一般性的公开说明，也可能不需要公开修改。修订的实际作用决定
它应当到达哪里；完整、直接的个人模型可以保持私有。
[从这个例子开始](example-and-commons.zh-CN.md)展开独立创作与公开内容的选择。

## 日月与大地：谁在参与？

[太阳、月亮与地球的意象](yinyang-and-taiji.zh-CN.md#太阳月亮与地球)把生成、接收与
赋形聚拢在能够回应的世界之中。人与模型是实际参与者；两边都能生成和判断，可以
保留或交换侧重，性别不分配位置。大地包含物质条件、他人的目的，以及双方无法
通过一致意见控制的后果。

这些意象、三个领域和三种实践形态，分别回答不同问题：怎样想象参与，哪些理解与
能力作出贡献，工作在哪里接续。本地程序的失败、协作者的替代方案、读者的异议，
都属于大地。在工作的流动中，这几组三项彼此映照，聚成同一幅图景。

## 为什么让语言模型组织它们？

三种形态之间的转换需要理解：一项方法回应的是哪种本地困难，一种解法的哪部分可以进入别人的环境，怎样的说明能让读者看见其目的。一个哲学前提发生变化，可能同时影响文章、图示、Skill，以及工具的实际使用方式。发现这种联系并判断该修订什么，既涉及文件操作，也涉及意义。

有能力的语言模型可以承担其中的工作：检索相关材料，比较不同论述，把不完整的想法发展成论证，把已形成的关系写成代码或指令，再检查实际行为。它也能发现人未曾打算接受的推论，并提出另一种解释。确定性工具则可以承担已经明确的渲染、打包和链接检查。语义判断与可靠的机械操作，各自贡献于同一项维护。

人可以通过对整体的辨认参与：这个联系合适，那段解释弄错了对象，这套安排现在已经有些过时。模型继续承担回答这种辨认所需的显式调查和构造。有相当推理能力的人，也可以选择把注意力放在哪里。与模型一起发展，能够包含分布在人、模型及环境之间的能力；[窃火的论证](stealing-fire.zh-CN.md)展开了这种培养。

不同模型可以分别调查来源、提出竞争解释或核验结果，只要这种分工对当前工作有用。
[隐喻、类比与个人的自我改写](metaphor-and-self-revision.zh-CN.md)展开外部表征在这种
分布式认知中的作用。安排须随实际能力改变：更强的模型可能让旧支架不再必要，
缺少工具也仍可能使合理解释无法实际使用。

## 一次变化怎样出去，又怎样回来？

以一项关于模型协作中学习的主张为例。本地工作中的旧描述，把逐步说明任务的责任过多交给了人。一个具体任务显出了代价：模型等待它本可自行调查的细节，工作因而停住。人察觉了不合，模型重建问题，并提出另一种分工。

本地关系可以被修订并接受尝试。如果其中有用的部分能在这次相遇之外得到表达，共享源内容就可以说明这项方法及其范围；网页再用例子和可见关系解释理由。读者可能指出，这个说明掩盖了一项重要选择；协作者也可能找到方法失效的场景。这些回应返回源内容，进入下一次本地使用。

这是穿过三种形态的一条示例路径。实际探究可以从其中任何一处开始。关键联系在于：变化有来处，有别人能够检查的形式，也有能够反过来修订它的后果。

互动、记录与解释作出不同贡献：事件发生，部分记录提供证据，解释提出事情为什么
发生。进一步使用能够纠正解释。[具身实验哲学](embodied-experimental-philosophy.zh-CN.md)
展开怎样让这些返回区分竞争解释。

## 让闭环保持当前可用

公开哲学已经凝缩了许多从个人材料中形成的理解。一项论证有了持续维护的公开表达，就从当前网页及其源内容回到私人工作模型，更新相关理解；重复的私人理论副本、被取代的解释，以及只是在复述文章的来源说明，都可以退出活跃材料。私人部分保留公开哲学不能提供的内容：相关的个人经验、具体处境、关系、目的，以及实际使用的证据。原始记录和旧版本仍在各自已有的归档中。

模型在相关、获授权的工作中比较当前源内容、受影响的原始记录与实际环境，再更新
有用的私人凝练及其使用处，用户不必逐条要求更新。计划、经验和配置分别说明不同
事情：意图可能尚未实现，配置可能来自默认值。当前经验也可能显出哲学的问题。
较新的时间戳或较旧的私人摘要都不能确定这项分歧，应考察主张及其根据。

## 什么是重点，什么作为材料？

这条闭环可以沿两个方向走。用哲学修环境，是看清 Skills 和工具应当实现的目的、参与关系与判断；用环境修哲学，是从实际使用看见某种理解在哪里妨碍工作、遗漏经验或不再贴合。心理模型把这两种运动接到真实的人，也会随之修订。

这次要修什么，由当前问题决定：

| 当前目的 | 修订重点 | 用什么帮助判断 |
| --- | --- | --- |
| 发展或纠正哲学 | 相关论证或模型 | 经验、私人情境和环境中的实际使用；采纳后的变化再回到受影响的 Skills 与安排。 |
| 修复个人环境 | 具体 Skill、配置、行为或工具 | 哲学说明的预期关系、当前个人模型与运行事实；显出的概念问题再回到哲学。 |
| 改好指定的局部 | 服务于预期结果的那个部分 | 从其他位置选取相关材料，只有必要的依赖变化才成为新增修改对象。 |

因此，一项内容变化可能需要同时改网页、私人模型与本地自制 Skills；Skill 开头的精神与具体方法都应表达变化后的关系。引号或等义链接名称的修改，通常就在呈现范围内完成。[环境适配方法](../harness-adaptation.zh-CN.md#选择当前重点沿两个方向修订)说明怎样把这种区别落实到实际工作。

## 融贯让差异继续相连

如果目的包括持续的个人使用、可检查的复用，以及能够被人理解的交流，那么这些功能各自需要安放之处，修订与反馈也需要在它们之间流动。这构成采用当前三种形态的理由。一个小任务可能只需要较少的形态，另一个环境也可以用不同工具实现这些功能。GitHub 与网页因其在这里带来的可能而取得位置。

融贯所关心的是三种形态之间有意义的关系：同一概念保有相关含义，例子保留其假设，页面能够通向它所解释的作品，共同修订到达实际使用者，私人理解则在真正需要它的地方可用。人改变了，关于人的理解可能需要改变；模型改变了，旧程序可能不再必要。保持融贯，也就包括让这些变化改变工作的组织。

这种统一持续发生着：哲学使关系可以理解，心理把关系接到实际参与者的生活，工程
通过计算模型重组关系继续发生的条件。人和模型共同承担这一运动，反馈能够修订
双方的问题、模型、实现与哲学理解。本地实践、维护中的源内容和可读页面，给工作以发展的地方。
这一切发生在同一物理世界之中；世界的回应能够改变作品及其创造者。
