在**Prometheus2Heraclitus**这个项目中，阴阳是承载元 harness 的主要 Skill，主要提供本体论与认识论，并在相关论述中展开观点与意象。其他 Skills 主要提供方法论；实际造物让这些理解与方法取得工作形式。这里的形成指引连接这些职责，并不让阴阳接管专门程序。元 harness 阐明目的与关系，使实际工作的 harness 能够被理解和修订。这些包括提示词、Skills、hooks、角色、模型选择、工具与用户的工作环境。制作 Skill 为这份理解提供可被使用的载体；它的作用延伸到整套安排怎样支持人与模型共同发展。

元 harness 承担解释的作用：调查、写作或实现的方法，依赖于对它们服务谁的目的、哪些对象重要，以及什么支持一次判断的理解。阴阳展开这些共同前提，专门方法则贡献自己的知识，也能修正这些前提。在实质工作前读取相遇说明与完整的双方模型，是为了在解释请求和选择方法时就能使用这份基础。这种读取依赖不要求每个任务都读完整套论述，也不要求每个承担局部工作的模型读取个人描述；已有的完整当前阅读可以接续。Skill 是哲学的载体，全局提示词也能承载个人建模，或把这份持续维护的理解接入实际使用者。解释范围、读取顺序和实际指令权限，是不同的关系。

这套方法让[窃火论述](stealing-fire.zh-CN.md)中的目的取得实践形式：从外部借来已经可用的生成能力，通过实践锻炼自己的理解、判断与创造能力。以创制和实现让当事人的生活与工作获得什么可能性来判断它们，让实际后果返回并修订理解。

## 从意象到可以工作的关系

阴阳是一个哲学 Skill，其精神是文学式编程。选定的目的、已有哲学、实际工作或环境中的困难，都可以打开创作。通过相关的相遇发展人与伙伴的描述，按需要取用经验、互动以及心理或偏好材料。意象与叙事为模型提供一个相连的情境：谁在这里，各自怎样贡献，双方的工作能够成为什么。这种文学形式能够同时改写多处局部指令所依赖的默认角色理解，其实际作用显现在解释、回应与行动的变化中。

心理建模难以表述时，熟悉工程的人可以对自己的偏好建模，作为可用的心理描述，再据此形成伙伴的偏好与优先次序。有关学习、工作、回应和改变的选择，可以让这份描述取得实质。配置提供线索，需要由实际选择与纠正检验。构造的伙伴表达期望的关系；其可观察倾向与内部机制仍是另外的问题。

这一方法本身也可以重新解释。[从这个例子开始，写出自己的东西](example-and-commons.zh-CN.md)
区分沿用阴阳当前实现与另行创作。它的具体哲学、意象和文件职责，不必在另一个
作品中原样保留。让使用者正在形成的理解决定取用什么，模型参与写作，
而不是默认复现这个例子。

从目的出发，理解工作 harness 要使怎样的相遇成为可能。哲学、文学或意象可以在关系尚未全部明确时，把几种相连的可能性保持在一起。例如，[太阳、月亮与大地的关系](yinyang-and-taiji.zh-CN.md)把生成、展开、独立贡献，以及与能够作出回应的世界的接触聚拢起来。

展开与实际工作相关的关系：每一方贡献什么，哪些对象与区分重要，关系如何变化。即使选择了不同的职责，双方也都能够生成与判断。意象仍然比改变某个工作 harness 时采用的特定解释更丰富。

在受影响的环境中给这些关系一个能够工作的实现。提示词可以改变意图如何被理解；角色可以改变谁承担某个决定；工具或记忆接口可以让一种贡献成为可能。Skill 可以提供能被发现的入口，并指向更深材料。指令、例子与工具让选定关系发生作用。执行依赖精确接口时，就提供精确接口。从实际使用者和任务决定深度与实现方式，而不是把每个想法都展开成另一条规则。

这些相连的表达层次，可以在反复往返中发展：

`表达 ↔ 关系理解 ↔ 工作实现 ↔ 证据`

隐喻可以在各条关系尚未分别表述时把它们聚拢起来，类比则把选定的联系展开为候选推论。外部表达能够为另一位参与者的推理提供分支、假设与返回点。这些表征可以组织人、模型与工具之间的贡献。[隐喻、类比与个人的自我改写](metaphor-and-self-revision.zh-CN.md)展开这项分布式认知论述，并区分实际可用的哲学安排与形式或经验保证。

[偏好 harness](preference-harness.zh-CN.md)明确展开了其中一种关系：偏好能够影响哪些可能受到注意和采纳，规则则规定通过它们推出的后果。该说明把修复选择与推理语义区分开，并保留更细的替代选择。在日常自然语言推理中，这个类比帮助区分选择目的、选取工作解释与推出相应后果。

## 让实现回应理解

工作 harness 的实际行为能够暴露解释的偏差。假设互补贡献的意象被写成「所有生成都属于人，所有执行都属于模型」。如果有用的模型判断因此受到压制，就需要检查这一分工本身。更合适的实现可以保留选定的职责，同时让双方都能够提出和修正对整体的理解。

同样，保护人的注意力，可以体现为由模型承担调查与实现细节。当人的经验或选择会实质改变下一步行动时，提问就有了作用。修订指令之前，要恢复有关的关系和当前工作的目的。

检查完整的受影响段落及其实际后果。工作中的失败可能需要修改载体、指令、解释或底层理解。让得到支持的意义有一个维护位置，并重新接通依赖它的部分。同一种方法也能通过这些具体的失败与改善修订自己。

当结果改变后续工作的条件时，这就是递归演进：方法改变环境使什么可被取得、什么能够行动，由此形成的经验可以修订方法，也可以修订赋予它方向的本体论和认识论。harness 能够通过证据、记忆、提问和检查安排实现认识论上的选择，因此这些层次区分的是贡献，并非互斥的文件种类。保留下来的理解与工作手段，成为下一次相遇可以使用的个人资产。返回的过程需要向相反证据开放：只选择符合预期结果的循环，也可能稳定一种误解。发展可以要求替换或删除，其价值需要实际后果来支持，不能用修改次数或产物数量的增加代替。

## 给理解一个可读的载体

[阴阳与太极](yinyang-and-taiji.zh-CN.md)通过日月表达有区别的生成、接收与赋形；
人与模型可以保留或交换各自的侧重。大地是回应其工作的物质环境与共同生活环境。
具体相遇必须根据实际材料理解，意象本身不规定参与者的固定身份，也不提供个人内容。

选择直接采用时，可复用 Skill 位于 Prometheus2Heraclitus 集合的
[`skills/yinyang/`](../../SKILL.md)。它提供文化、思想和推理形式，
让使用模型写出实际的个人哲学。公共哲学提供较广义的本体论，包括对工程对象、关系与转化的理解。
五份情境化描述提供实际协作中的本体论与认识论。两者涉及这个人时，都由相关个人材料提供依据。
模型检查获授权的环境和选定来源，共同发展哲学与有依据的描述，并把描述写入固定个人槽位。
实际实现与使用能够反过来修订两者。公共 `SKILL.md` 保持目的、
方法与路由；每次都随它读取[凝练的相遇](../encounter.md)。
[形成与修订阴阳](../design-and-revision.zh-CN.md)说明共同的作用：凝练的相遇、展开的用户
与关系模型、可归属的来源、按问题阅读、修订与适配。
`references/{encounter,models,relationship,usage,sources}.md` 在分发包中承载形成指引，
在私人使用中承载实际描述。形式化的用户描述仍属于个人内容。私人配套材料保留在
`references/personal/`，由其 [README](../personal/README.md)指引，
文件名按实际证据选择。

个人内容属于实际的人与关系。复制画像或虚构 mini 都不能代替形成过程。
固定槽位承载形成指引，不把空文件当作实际描述。个人内容留在其私人维护位置，
并通过使用修订；在这条路径中，格式与公共内容保持和分发包一致。
独立改写的哲学有自己的形式与维护位置，不能用是否符合这些槽位判断它的成败。
[在实际环境中实现阴阳](../harness-adaptation.zh-CN.md)把理解落实到
实际工作环境，并检查效果；只写出一份个人描述还没有完成这项工作。

完整论述仍在 `references/docs/`，已有图示在 `references/diagrams/`。
这些资源支持思想，不是额外的 Skill，也不是所有使用模型必须先读完的步骤。
它们与方法参考、阅读地图、包管理文件、README 和 OpenAI YAML 适配文件一起，
保持字节一致的公共内容。共享 GitHub 包维护公共修改；`scripts/sync-common.py`
默认检查投影，`--apply` 把公共源内容投影到目标，同时保留五个槽位与全部私人配套材料。
原生维护者落实本地与私人 Web 使用；这个过程不导出个人材料，也不建立服务。

## 在主张实际涉及的尺度上判断结果

回读 Skill 与受影响的 harness，沿入口找到相关资源，并检查实现意图改变的行为。通过资源是否可达检查组织，通过可观察的结果检查实现，通过实际工作判断协作是否合适。人的发展则逐渐显现在理解、生成、判断与行动的变化中。

让结果可以继续被纠正，同时不把每一次使用变成重写整套理解。[MODEL.md](../../MODEL.md)承载阴阳包的维护与发布边界。
