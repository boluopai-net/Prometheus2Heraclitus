# 阴阳的实践总览

[首页](../../README.zh-CN.md) · [工作模型的形成与修订](../design-and-revision.zh-CN.md) · [阴阳的日常协作](../../SKILL.zh-CN.md) · [English](creation-method.md)

形成自己的阴阳，是把采纳的观点、对实际参与者的理解，以及双方可以共同工作的环境连接起来。
它要成为进入生活的实践：你与有能力的模型伙伴一起，能够理解、创造、判断和做什么。
作者的[窃火](stealing-fire.zh-CN.md)把它展开为通过借来的生成能力培养自己。你自己的哲学可以
采用、组合、质疑与改写已有思想，形成自己选择的方向。

## 哲学与模型共同发展

先选择有助于理解实际问题、经历或工作方式的观点，在工作描述中说明采纳了什么。
对哲学写作有兴趣时，文学、人文、工程、逻辑与美学可以为进一步的作品提供材料。
维护阴阳的按问题形成的模型，并不要求另开这个写作项目。

哲学阐明概念、理由、价值与可能，个人材料为它们如何适用于实际的人、伙伴与关系提供根据。
两者都能够修订对方。选定方向有别于对体验的解释；期望模型作出的贡献，有别于已展示的能力。
[工作模型的形成与修订](../design-and-revision.zh-CN.md)展开这些联系，并通向工作模型的写作指导。

起点与顺序可以不同。你可能已有哲学表达、个人探究历史，或工作环境，由此发展缺失的联系。
工具或作品可以揭示一种关系，随后它才取得哲学表达。选定观点、可修订的个人材料与实际安排
可以共同发展，是否把这些理解进一步写成文章，由兴趣决定。

## 从形成指南到六个工作模型

六份指南分别说明取向、人、伙伴、关系、环境与修订。简单路线是请语言模型阅读已采用的哲学与
相关新来源，纠正受影响的 Personal 理解，再直接综合为 `references/situated/` 下六份可读文件。
一起阅读六份完整正文，检查相互融贯，落实需要的 Skill 与环境改动，再从使用中检查效果。
Git/GitHub 可以持久保存文件与版本；个人正文和来源应留在私人存储或私有仓库。
这条路线不需要记忆服务或 API 配置。

历史更复杂时，[Hindsight](../hindsight.zh-CN.md)提供可选实现，使用保留、Observations 与按问题
定义的持续维护页面。按实际环境选择配置，不照搬他人的设置。它保留同样的六项功能与修订依赖。
原始来源保有维护者；Personal 的四个主题组，无论直接编辑还是通过原生页面维护，都保留有实质
内容的可读文章，Observations 在后台工作。原生产出同样需要一起阅读，并通过实际使用检查。

[工作模型的形成与修订](../design-and-revision.zh-CN.md#基于实际材料形成情境化版本)连接不同内容视角。
完成产出、协作适配和人的发展是不同主张，需要通过实际使用取得相应证据。

## 使用阴阳

人与模型可以共同阅读和使用这些材料：发展论证，将说明与经验比较，检查安排，或完成获授权的
变化。不同写作形式服务不同贡献，不把哲学专属地分给人，也不把实践理解专属地分给模型。

[阴阳的日常协作](../../SKILL.zh-CN.md)说明当前工作模型怎样在日常工作中协作，[包结构说明](skill-package.zh-CN.md)
说明其公共与私人路径及共同更新。这些是相连的入口，不是每项任务都要重走的步骤。
[从采用、组合到自己的创作](example-and-commons.zh-CN.md)邀请选择性采用、组合与独立创作。
