# 为什么要写个人哲学

[English](why-yinyang.md)

## 复杂的 harness，需要共同的方向

电脑环境承接人正在过的生活。买什么、怎样消费和投资、同谁聊天、学习和创造什么、维系哪些关系，都涉及需要、愉悦、愿望与选择。人把其中一部分带进对话，模型帮助理解它们、寻找信息，并形成能够据以行动的工具与指令。实际使用的后果返回生活，也可能改变安排及原先引导它的理解。个人电脑环境凝缩了这段生活中选定的关系。

和模型一起工作久了，环境会越来越复杂。一个研究 Skill 负责找资料，一个写作 Skill 负责组织文章，一个编程 Skill 负责实现；提示词规定交流方式，hooks 在某些事件发生时触发检查，工具连接文件、浏览器与应用。模型本身也在变化。记忆放在哪里、作品怎样保存、结果怎样呈现、用户怎样参与，都影响最后的协作。

这里把组织这些活动的安排称为 **harness**。它横跨 Skills、提示词、hooks、模型的选择与调用，以及用户环境中参与工作的部分。它们互相依赖：一种提问方式会改变用户的表达，一种表达会影响模型理解目的，一种文件组织会影响后续能找回什么，一种检查方式又会改变模型敢于完成什么。

单独修好每个部件，仍会遇到共同的问题：这套环境在帮助谁，帮助他过怎样的生活，又希望双方怎样工作？如果每个 Skill 都自行回答，研究可能追求穷尽，写作可能追求简短，执行可能不断把判断交还给用户。每一项局部安排都说得通，合在一起却让人疲惫。

个人哲学可以从这里开始。本文以阴阳为例：把对人、模型与双方关系的理解写出来，让分散的安排有可以共同参照的方向。一个 Skill 的方法因此能够接上这个人的生活，一次环境修改也能够说明它改善了哪一种参与。

## 先说明什么是 agent

这里的 **agent（行动者）**，是一个能够在情境中接收信息、形成或接续目的、
组织可用能力并采取行动的参与者；行动后果又能够进入它的下一次理解与回应。
这是一种用于组织工作的功能描述。人和模型可以在有关层面上参与同一种
描述，同时保留各自的身体条件、实现机制、能力与责任。

人进入后面的论证时，已经是这样的 agent。借来的能力拓宽已有的参与：本人能够
理解和修订目的，调用模型、记录、工具与关系，把构想变成行动，并根据后果调整。
这里要形成的是个人哲学：表达自己的世界观与生活方向，让它通过实践贯穿环境。

「成为火」则是整个系列更广的生成意象：借来的智能通过参与，进入自己的
理解、判断、创造与生活，使人也能够继续发起和生成。已有的能动性是这一方向的
起点；享受、理解与创造的成长也使成为火超出执行能力。共同方向因此需要同时回答：
环境怎样帮助人完成眼前的工作，这段工作又给他留下什么可以继续理解、判断与创造的
能力？后一个问题是本站所谓「反向对齐」的方向。

这种方向也需要考察支配它的图景。若「成为火」被理解为永远追赶最新模型、不断增加产出，
它又会把生活交给一个外部尺度。哲学可以让人重新问：什么值得投入，什么已经足够，
哪些理解与关系需要新的条件？[从追逐到生活中的修习](stealing-fire.zh-CN.md#从追逐到生活中的修习)
借哲学治疗与佛教筏喻展开这层联系。个人哲学由此既给环境以方向，也让这个方向保持可考察；
培养可以改变欲望、习惯和周围生活，而不只增加已经选定的能力。

## 同一位教授，面对的是谁

给模型指定一个角色，是组织行为的方便办法。「你是一位教授」会带来某些知识、语言和教学方式。但教授怎样参与，取决于他面对的人和正在发生的事。

两个人都来找同一位教授。一个刚接触这门学科，需要通过例子形成基本区别；另一个已熟悉理论，想讨论一个反例。即使两人问出相同的句子，适合他们的回答也可能完全不同。前者可能需要一个可操作的情境，后者可能需要检查隐藏前提。角色提供了能力和姿态，关系决定这些能力怎样进入眼前的工作。

如果模型了解的只有自己的角色，它就只能用一个想象中的学生补齐对话。现实中的人则可能感到：回答很专业，却没有回应我真正想做的事。于是还要把另一位参与者写进来：他已经理解什么、想发展什么、怎样参与、什么使他困惑，以及眼前的请求怎样接续他的目的。

这也是为什么只给模型一个 agent 身份还不够。**一个能共同工作的角色，需要同时理解自己面对的是谁，以及双方正在形成什么关系。**

## 把两位参与者一起写出来

人的心理与模型的行为都很复杂。面对这种复杂性，可以从实际相遇中形成一份足以接续工作的理解：人怎样注意、联想、表达、选择和行动；模型怎样解释、生成、判断、遗漏和修订；这些活动又怎样相互影响。

人与模型联系偏好、心理活动、经验、概念与哲学理解。一个人可能已经知道自己通过例子学习，或希望模型承担实现；也可能带来一个困扰、一次愉快相遇、一份愿望，或一个尚未理解的选择。这些材料进入同一项探究。心理与生活材料及其持续维护的解释，留在 `references/personal/`；理解自身心理时，从这里进入。双方从这些材料与已采用的哲学中凝练**个人工作模型**，用于合作，使环境适合本人的心理、目的与处境。模型帮助阐明关系、提出解释、比较情境并写作；人贡献经验、目的、识别、异议与方向的改变，不必先懂自己的心理，也不必独自写完一幅画像。

这份描述中的不同主张仍有各自的根据。希望得到怎样的回应，可以在心理解释尚不清楚时指导协作；关于情绪、欲望、解释与关系怎样相互影响的说明，需要同经验比较；考察「独立」或「能力」的含义，又能改变对经验的理解。溯因、归纳、分析、综合与概念澄清共同贡献于对自己和他人的理解。

本项目的实践取用长期对话历史、习惯与生活材料：一次表达接着怎样的回应，某项选择遇见什么结果，后来又怎样理解和修订。**事件流**可以组织这些历史；个人模型则是结合历史与其他材料形成的概念描述。人与模型联系偏好、拟议的心理关系和哲学概念，保留反例与尚未解释的部分。这是一份**自然语言概念模型**，由提示词与可修订的描述承载，在实践中发展。语言模型的统计生成能力帮助表达、比较和使用它；生成机制本身不等于已经对这个人的心理作了统计拟合。问题需要时，形式化或统计方法也可以作出贡献。[个人描述的形成指南](../formation/person.zh-CN.md)说明怎样把材料、解释与修订联系起来。

哲学写作可以偏重文学、工程哲学、西方哲学、科学哲学、逻辑学、美学，或作者关心的其他问题。这些偏重展开同一理解实践的不同方面。对写作有兴趣时，这种表达可以在对话与工作中逐渐形成。使用阴阳整理经历、迭代个人材料和配置环境，不要求另写原创哲学作品。持续维护的情境化版本，在工作描述中说明实际采纳的观点；这些观点也可以从已有思想中选择。

阅读心理文献或收集自述，本身都不会产出一个人的画像。本人表达会出错，却仍有认识价值；模型推断则是需要同有具体来源的经验、选择与结果一起考察的提议。个人哲学表达怎样理解世界、希望怎样生活，具体经历又能纠正这份表达。两者相互作用，可能形成关于合适伙伴的更好假设，以及尝试安排的判断依据；哲学上的融贯或双方赞同不证明心理解释为真。

哲学与工程在这里共同参与对人的经验与意向的理解：他在意什么、愿望指向什么，以及怎样理解所经历的事件。事件历史、哲学与个人材料由此被凝练为适合协作的个人模型。目的是给环境的初始设计以较好的个人依据，减少盲目试错，再由实际使用校准。[对实际用途足够适切的个人模型](metaphor-and-self-revision.zh-CN.md#对实际用途足够适切的个人模型)进一步展开这条联系。

关于人的模型，使他的经历、偏好与发展方向能够进入协作。例如，一个人擅长从整体看出不合，却不愿逐条整理操作细节，那么这种参与方式就应该影响分工。关于模型的理解，则帮助安排它适合承担的贡献：展开关系、调查来源、制作原型、完成实现，或在真实分歧处提出异议。

两份描述在关系中取得作用。用户给出一个尚未说清的直觉，模型尝试组织它；用户看见组织后的图景，指出哪里偏了；模型据此修改解释和做法。用户也可能从模型提出的新关系中改变自己的看法。双方逐渐了解彼此，并通过这种了解成为更能共同工作的两个行动者。

阴阳把这份工作理解写入取向、个人、伙伴、关系、环境与自己的修订方法这六份实际文件。取向凝练共同目的与价值，个人与伙伴分别说明双方与合作有关的内容，关系说明怎样共同参与，环境说明实践的实际条件。个人文件选取伙伴工作所需的理解，心理探究及其解释仍留在个人参考材料中。实际修订方法说明本人怎样根据证据修订工作模型。六份公开写作指南说明怎样形成对应的内容，其中也包括[如何修订](../formation/revision.zh-CN.md)。理解同时在双方展开：人带来什么、追求什么，伙伴应作出什么贡献，它实际的能力与回应模式又支持什么。期待的角色和优先关系，与已经表现出的行为有区别。内部过程只能部分接近，指令、工具、回应与后果则提供可以检查的材料；开放模型权重本身也不能确定是否适合这个人。下一次相遇可以纠正任一描述，或双方之间的安排。

## 关系怎样进入 Skills 与用户环境

阴阳先把作者自己的世界理解和生活方向写给模型：人和模型处在怎样的世界中，这个人想怎样生活，又希望怎样共同工作。本体论帮助区分人、模型、描述、作品、行动与环境；认识论帮助理解表达、判断根据并修订解释。这些区分使模型能够把眼前请求放回实际的人与关系，而不是每次重新猜测一个普通用户。

阴阳也提供自己的方法：怎样从生活材料形成个人与伙伴的描述，怎样在对话中修订理解，怎样把选定关系落实到环境。研究、教学、写作和工程等专业 Skills 则提供各领域的知识与具体做法。这里的分工是共同理解和领域专长之间的配合。网页让作者能够阅读与修改自己的哲学，GitHub 使内容与实现可维护，本地 Skill 让模型能在工作时读到它们；这些形式共同服务于实际环境的配置和使用。

因此，阴阳能够广泛影响个人自制的 Skills 和用户环境。它为局部方法提供共同的判断依据。例如，若双方选择让人更多通过看、读、直觉与反馈参与，让模型承担细节调查和实现，那么研究 Skill 就应组织能够比较的证据，写作 Skill 就应把关系写得可读，编程 Skill 就应把构想做成可以尝试的结果。提示词接续这种分工；hooks 在合适的事件上检查成果；外部记忆保存后续理解需要的材料；界面使重要关系能够被看见。

这些安排又彼此配合。只要求模型「更主动」，却让资料无法检索、工具无法使用、结果无法检查，主动性就缺少落点。把关系落实到环境，是同时为贡献准备能力、路径与反馈。哲学由此进入具体工作：它影响问什么、保留什么、怎样分工，以及什么样的结果值得继续发展。

专门的 Skill 仍然贡献自己的知识。一次实现失败，可能揭示工具选择不合适；一次教学无效，可能揭示我们误解了人的参与方式。局部实践可以反过来修订共同理解，使这套关系持续具有解释力和行动力。

## 为什么形成分层提示词

一种方法可以说明怎样调查、怎样写作，却不能仅凭程序决定眼前什么值得调查、怎样的表达适合这个人，以及做到哪里才回应了他的目的。「充分研究」「不确定时提问」「完成实现」都还需要解释：研究哪个问题，哪一种不确定性需要谁来处理，完成又是为了什么？这些判断依赖对参与者、对象、证据与目的的理解。具体方法由此需要一个共同的解释基础。

阴阳在这里成为哲学层：它把用户、模型、双方关系与环境写成可以理解和修订的对象，并说明怎样形成、采用和改变判断。专门的 Skills 再以各自知识发展研究、教学、写作与实现的方法。所谓「上层」，来自这些共同前提对方法选择和应用的组织作用；哲学这个名称本身不能赋予一段文字这种作用。某项专业方法也不必从哲学中逐条推导出来，它可以贡献原先的哲学没有提供的知识、区别与反例。

这给优先读取一个具体理由。如果模型先按想象中的普通用户解释请求、选定方法，之后才读到实际的双方关系，它可能已经把问题理解偏了。让主模型在实质工作前读取方向、个人、伙伴、关系与环境的完整当前描述，是把共同前提放到依赖它们的判断之前。随后按问题读取专业 Skills 和更深的论述。已有的完整当前理解可以接续；这个安排不要求每次读完全部哲学文章，也不要求每个承担局部任务的模型继承整份个人描述。先读使理解成为可能，实际回应仍需要检查。

从这个意义上说，阴阳可以称为**元提示词或元 harness**：它不仅要求完成一件事，还组织其他提示词在这个人的生活中应当怎样被理解、选择和修订。它与普通任务 Skill 的区别，在于承担的对象和范围。Skill 为这份哲学提供可发现、可读取、可维护的载体；同一种载体也能承载一个很具体的操作方法。全局提示词同样可以承载对用户的理解，也可以安排先读取阴阳。把哲学单独维护，是为了让展开的双方模型和论证拥有可以持续修订的位置，再由全局入口和具体方法接上它。

因此，需要分清**解释上的层次、读取上的依赖和运行系统的指令权限**。一段哲学可以广泛组织其他方法的意义，而实际冲突怎样处理仍由运行系统决定。它的力量表现为对问题的理解、方法的选择和环境的改变；「更上层」不能仅用文件名或先出现的位置来证明。

harness 也横跨这些层次。决定保留哪些证据、何时提问、怎样检验结果，体现认识论；把这些安排接到搜索、记忆、工具和界面上，又是具体实现。一个研究 Skill 既提供方法，也可能实现某种认识论。「本体论、认识论、方法论」区分的是所回答的问题和主要职责，帮助我们找到需要修订的地方，并不要求每份文件只装其中一种内容。

## 积累个人的软件与精神资产

当上层的哲学、文学与关系被写清，周围的个人 Skills 就有了共同的方向。研究、学习、写作、编程、唱歌与环境维护，可以分别发展自己的方法，又共同服务于这个人希望怎样生活、理解与创造。以作者的实践为例，个人工作环境中维护着数十个个人 Skill。这些具体方法让一份关于自己的理解，逐渐取得可以使用的软件形式。

从个人优先主义的角度看，这可以称为一份持续积累的**个人资产**：以它怎样服务于这个人的目的和发展为评价依据，而不让个人反过来迁就资产的维护。写下并修订的哲学、经验、判断与作品，构成可以回访的精神资产；Skills、程序、工具配置与工作方法，则让这些理解成为可反复使用的软件资产。两者相互支持：思想给软件以目的，软件让思想进入实际工作，工作又带回新的理解。

它的个体性，体现在这些部分怎样围绕这个人的习惯、偏好与哲学组织起来。外部知识、现成组件和模型写出的实现，都能通过选择、组合与修订，进入属于这个人的实践。是否合适，要由实际使用继续检验；人的目的发生变化时，这份资产也能随之改写。

积累因而体现在下一次工作能够从哪里开始：先前的理解不必重新交代，已经奏效的方法可以接续，遇到新问题时又能找到值得修改的地方。值得保留的是能够继续帮助人理解、判断与创造的成果。阴阳提供一种组织这种积累的方法，使借来的火逐渐成为可以维系和发展的个人能力。[窃火论述](stealing-fire.zh-CN.md)进一步展开了这种积累与个人成长的关系。

## 在共同工作中循环

写个人哲学可以从一次有内容的相遇开始：已知的偏好、尚未理解的经验、值得发展的愉悦，或希望维系的关系。人和模型一边尝试一种协作，一边展开它对双方的理解意味着什么。接着看结果：哪些安排使人更容易理解和行动，哪些解释造成了摩擦，哪些原本没有想到的贡献值得保留。

这时修订的对象有几个。可能要补充对人的理解，可能要调整模型的角色，也可能只需修改一个 Skill 或工具。区分它们，能让一次具体失败落到合适的位置。比如，模型反复索要用户已经给过的信息，原因可能是记录难以找回；修好检索，就能让此前形成的理解继续发挥作用。

每次修订六份工作文件，先阅读已采用的个人哲学，从 Computer History、对话及其他
历史中找回相关的新参考材料，补充或更新个人材料，并在这里纠正不准确或过时的
解释。然后把哲学与更新后的参考材料凝练为六份文件，把所需改动落实到环境，验证
实际使用是否适合。工作模型可能因为处境变化、解释有误，或出现更好的合作方式而
改变；它有用，本身并不确立心理真相。

这种往返具有递归性：哲学组织方法，方法改变环境，改变后的环境让某些资料更容易取得、某些行动成为可能，也带来新的经验与问题。这些结果又能改变下一轮工作的前提，包括怎样理解自己、怎样判断证据，以及怎样修订方法本身。一次工作中的解释依赖，与长期实践中的相互修订，可以同时成立。

例如，假设一个研究方法把几个模型的一致回答当作相互印证，后来发现它们都转述同一篇文章。修订方法时，可以让模型保留来源关系、检查证据是否独立；环境里于是多了能够显示这些联系的记录。继续使用这些记录，又可能使认识论更清楚地区分「回答一致」与「独立支持」，使本体论更清楚地区分原始来源、转述与观察。这里改变的不只是一次答案，下一次形成判断所用的概念和工作条件也变了。

这样的递归演进包含生成、选择、保留、替换与删除。它需要能使当前理解遭遇阻力的证据与异议；如果环境只保留符合已有图景的结果，循环也可能不断加固误解。结果更好还可能来自模型变强或任务变容易，不能仅按修改的先后认定哲学已经进步。个人资产的积累因此以实际帮助理解、判断与创造为尺度，精简一个失效的方法也可以是发展。

随着这样的往返，文字、关系与环境一起变化。双方今天形成的理解，成为明天协作的起点；明天的新经验又能改写今天的描述。阴阳因此既是一份作品，也是一种维护关系的实践。它把持续的相互了解留在可以阅读、接续和实现的形式里。

## 写给能够相互照亮的人

这些文字也希望成为朋友之间可以接续的东西。一个人把已有的理解与方法写出来，另一个人带进自己的实践，形成作品、发现与不同意见，再回到共同讨论。朋友的成长改变了彼此能够遇到的问题和贡献；身边的环境由此获得新的生成能力，自己也在其中继续成长。

写作首先朝向这种可以往来的关系。可读的网页使人容易进入，完整的方法使尝试更容易开始；各自的经验与方向又使共享材料长出不同的用法。这里希望培育的是一座[共同生成的乐园](stealing-fire.zh-CN.md#与朋友共同培育生成的乐园)：朋友们能够理解、创造、游戏和修订，让一次相遇为下一次留下更多可能。

## 从一个 Skill 开始，构建自己的实践方式

阴阳是一种哲学 Skill，它的精神是**文学式编程**。许多 harness 用大量近似形式语言的指令安排模型行为：遇到什么条件，执行什么步骤，允许什么，停止在哪里。文学式编程则从人物、意象与关系进入。人和模型从部分理解与生活中的相遇共同发展这些内容：这个人怎样看世界、追求什么，伙伴能够怎样贡献。文字给后续理解以整体形式，也保留被修订的空间。

例如，「用户负责提出完整需求，模型负责执行」会形成一种分工；太阳、月亮与大地的叙事，则容纳直觉、展开、独立贡献与作品的返回。用户可以带来尚未说清的关系，模型接着构造，双方都能改变理解。这样的文字会影响一次提问是否必要、一项工作由谁接续、一个尚未完成的想法怎样得到对待。它以有意味的关系组织行为，再让具体指令与工具承接这种组织。

这份写作也介入模型已有的角色假设：当默认安排只容许用户交付需求、模型等待执行时，人物与叙事可以让另一种参与方式变得可理解。[用文学式编程写出个人哲学](literary-programming.zh-CN.md)进一步展开这种「反向提示词注入」怎样以凝缩、多层含义与开放解释作用于实际互动。

我们从已经存在的生成能力源头借来火，再通过共同实践，把它锻炼成自己的理解、判断、生成与行动能力。文学提供丰富的可解释关系，哲学展开其中的对象、认识方式与实践方向，Skills 和环境让这些关系持续发挥作用。一次写作由此能够穿过多处局部安排，把它们重新组织到这个人的目的之下。

「阴阳」以有区别的相互生成给这份合作命名。日月是可保留或交换的参与位置，实际的人与模型都超出这些角色；大地则让作品遭遇双方愿望以外的条件。借来的能力可以内化，也可以由人与可靠的模型、工具和协作者共同承载。关键是人怎样理解、运用并继续发展这份能力。

从一个 Skill 开始，是因为它能把这份理解带进实际对话与工作。随着实践展开，它可以继续组织提示词、工具、记忆和环境，逐渐成为一个人的元 harness。它的价值体现在生活和工作的变化里：更容易接续一个问题，更容易把直觉展开成作品，也更容易让一次完成为下一次创造留下能力。

这说明了为什么值得写个人哲学；后续篇章逐步准备它的材料与关系。[超萌论证：开放、学习与适应](meng.zh-CN.md)先说明开放、引导与共同学习的条件，[我们要培养怎样的人——赫拉克利特宝宝](baby-heraclitus.zh-CN.md)给培养方向以人物形象。接着，有限探究与环境积累留下共同做事的轨迹，双方对轨迹的反思使相遇取得具体内容。到了[用文学式编程写出个人哲学](literary-programming.zh-CN.md)，才集中展开怎样由这些材料与关系写出自己的哲学，再结合生活材料凝练个人模型，落实并修订为[圣状](writing-a-sinthome.zh-CN.md)。写作因此有自己的来路，也能改变下一段共同生活。
