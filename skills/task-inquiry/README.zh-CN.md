# 任务探究

**通过证据、推理与有用的问题，澄清会影响行动的未决问题。**

[English](README.md)

任务探究帮助助手处理那些会改变任务下一步行动的不确定性。它从真实的
分歧或不符之处出发，形成可检验的解释，再通过证据或针对性提问加以区分。
助手承担调查与推进工作，不要求用户先把问题整理成完整规格。

## 怎样使用

通过你的助手所支持的 Skill 机制提供完整的 `task-inquiry/` 目录；当重要歧义、
相互冲突的解释或未决选择会影响任务时，调用**任务探究**。本包的独立指引位于
[`SKILL.md`](SKILL.md)。它不依赖特定的配套框架、私人上下文、脚本或服务商集成。

只有探究能改善结果时才使用这套方法。目标清楚、条件已定的任务应直接推进。
只有答案会改变解释、证据或行动时，提问才有意义。

## 示例

**调查意外结果。** 报告的总数与仪表盘不一致。助手检查日期范围、筛选条件和指标定义，
找出哪些差异可能解释不符；只有现有证据无法确定预期报告周期时，才向用户询问。

**澄清重要偏好。** 两个方案都能达到既定目标，但一个更省时间，另一个保留更多灵活性。
助手说明这项取舍，并在执行依赖该选择的步骤前询问用户更看重哪一项；同时继续独立的调查工作。

## 方法概览

助手先找出真实分歧，区分事实、假设与未知，再提出值得检查的解释。它推导不同解释
各自应带来的差异，收集现有证据并据此修订判断。在普通工作中，只有证据无法提供答案、且答案
会改变工作时，才向用户询问信息或决定。教学也可以通过提问显露或发展理解，见下文。实际交互与授权
仍遵循当前宿主的边界。

## 工作与学习

在普通工作中，有用的反馈可以帮助用户看见某种关系：说明当前解释推导出什么，证据又显示什么。
助手仍承担推理和执行，不额外安排课程或练习。在教学情境中，即使答案已知，也可以通过提问和练习
显露或发展学习者的理解。教学角色依据学习目的选择方法并负责进度；这套探究方法不会把教学形式
强加给普通任务。
