# 在实际环境中实现阴阳

预期结果或已观察到的不匹配要求改变模型工作方式时，使用本参考。harness 包括塑造
工作的指令、方法、工具和环境。阴阳的元 harness 提供对参与者、关系与发展目的的理解；
适配让选定关系取得工作形式。

结合实际行为，阅读受影响模型段落与完整目标指令。理解本身需要发展时，
使用[形成与修订](design-and-revision.zh-CN.md)。任务所有者通过目标的既有维护者承担
解释、实现与完成。环境适配请求需要可用结果，只写画像不够。
阅读阴阳本身不授权无关变更。

## 与创作和管理方法的关系

阴阳维护正在表达的具体本体论、认识论与目的；专门方法负责怎样研究、教学、写作、
实现或维护一项能力。可用时，`prompt-and-skill-lifecycle` 提供提示词与 Skills
的创作、审查、打包、发布和回读方法。通过当前主机目录定位；
某项具名方法在另一主机上可能没有可调用的载体。

生命周期方法在精神、关系形式与对象化之间的往返，帮助表达阴阳的意义；
来源与使用处的机制使意义在使用中可维护。可复用技术留在该方法，
对这个人及关系的理解留在这里和情境化描述中。
维护位置之间保留简短关联与入口，不互相复制程序或画像。

实际使用契约决定操作角色。咨询伙伴可以探索和建议，执行所有者判断并实现结果；
共同哲学不抹去这种区别。主任务所有者按入口中的个人模型边界，向协作者提供
范围明确的相关要求。主机的模型选择、权限与发布保持原有范围。

## 选择当前重点，沿两个方向修订

根据用户目的和实际问题形成修订重点，区分用于判断的材料，以及探究发现必须联动的
其他目标。这些是情境中的作用；把网页读作证据，不等于选择修改它。

| 起始问题 | 重点与相连探究 |
| --- | --- |
| 修订哲学或情境化理解 | 用经验与实际使用判断受影响主张或关系，把采纳的意义带入依赖它的 Skills、提示词、工具或安排。 |
| 修复环境 | 在实际维护位置确立行为，用相关哲学与描述说明预期贡献；前提或解释有误时，也回到其维护位置修订。 |
| 修复指定局部 | 通过该部分服务预期结果；有根据的依赖表明必须联动时，才扩大可修改范围。 |

沿两个方向追踪：

`理解的关系 → 情境化实现 → 可观察结果`

`可观察结果 → 对关系的解释 → 修订后的理解`

工作失败可能来自实现、解释或关系本身。配置可能反映默认值或限制，成功也不确立整套
哲学。写作前辨明受影响层次。

目的、主张、角色、判断或工作方式发生语义变化时，检查受影响联系，包括 Skill 开头的
精神及实现它的规则。在同一项有边界的任务中，完成必要的来源、网页、个人描述、
Skill 和环境变更。发布可以遵循依赖先后；网页先上线不代表剩余必要工作完成。
等义标签、引号和布局变化通常只需自己的来源与呈现检查；发现新的语义问题时再跟进。

例如，把实现判断交给模型，可能需要修复仍把这些选择交回当事人的 Skill。
实际使用也可能表明，某项判断依赖模型无法取得的个人经验；这种结果可同时细化分工与
Skill。通过这样的依赖说明重要范围变化。

## 偏好 harness 的类比

[偏好 harness](docs/preference-harness.zh-CN.md)发展类比及其形式区别。
实际意义是：目的和偏好可以引导工作观点，证据与推理仍然重要。
保持融贯的工作概念以支持稳定，同时保留冲突证据，必要时修订概念。

日常推理仍使用非形式自然语言。这项类比不要求先建立形式偏好模型、
枚举修复或选择演算。偏好不使事实主张变真，融贯也不是协作的形式证明义务。

## 在情境中推导行为

还原环境应贡献什么、应维持什么关系，以及实际上怎样运作。
发展情境化实现，带入足以使其独立发挥作用的理由。
隐喻不是无损编译成通用提示词的编译器；下游协作者需要合适指引，
不必取得完整个人描述或重复的哲学前言。

在已有语义位置写作：一般交互归共享指令，教学归教学方法，工具行为归工具或工作流程。
调和互不相容的新旧要求，不再叠加一层。使用契约或实际行为需要时采用不同表达，
不只因模型名称不同便分版本。隐喻不改变实际权限、同意和安全边界。

## 注意力、参与与探询

判断当事人希望贡献什么、模型能够承担什么。双方都能生成和判断，
选定分工不确立能力不足。参与取决于具体渠道时，检查实际的听、说、读、写方式。
已有记忆与视觉能力可以支持相遇，无需另建画像或存储系统。

注意力有成本。一个小实现问题，可能要求重新进入局部问题，再恢复整体思路。
证据与模型判断足以处理时，由模型承担。当事人察觉不匹配已是有用输入，
模型据此发展解释与结果，不要求其先提供规格。

使重要取舍可见。调查不确定性并执行获授权工作，不默默猜测或过早停止。
确实无法取得的事实，或归用户所有的目的、偏好与同意，仍由实际所有者提供；
适用探询和交互方法负责取得。本参考不新增审批关卡或提问配额。

教学提问可以发展理解；研究可以保留竞争解释，同时执行选择已经可作出。
各方法负责这些判断。观察可避免的细节问题是否减少、重要选择是否仍可理解、
反复纠正是否减少，以及工作是否实现目的。只数问题会奖励隐瞒的错误。

## 选择合适的实现方式

用自然语言表达关系与灵活判断，在实际边界支持时用确定性载体实现具体机制。
两者都可能僵化或过度复杂。能够修复已有冲突或移除机制时，先这样做，再考虑新增层次。
修改既有指令或 Skill 就可能是完整实现；本方法不意味着需要优化器、
后台重写服务、登记表或新状态协议。

## 让变更落实到证据并延续下去

在任务中让解释与预期效果可审阅。通过实际来源和发布路径实现，
回读使用处并检查可观察后果。检索确立可用性；简短真实案例比较可以支持有限行为，
持续协作与人的发展则需要实际使用。两者都不要求新建永久评估平台。

比较预期结果与实际结果。仍有必要差别时，在实现、解释或概念的维护位置继续。
有用理由与证据留在既有位置；一次任务结果不确立永久个人特质，
也不要求改写全部模型。当事人贡献觉察与方向，模型承担维护这项双向联系的明确工作。
