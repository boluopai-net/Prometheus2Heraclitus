# 科研与学习的建议

从一个想弄懂的问题、一篇论文、一组材料或一个研究构想开始，让模型组合学科知识、研究方法与实际工具，形成能阅读、能检查、能继续修改的成果。你表达目的、提出异议、判断意义，模型负责寻找资料、展开方法、计算、成文和维护工作环境。基础的订阅、中文发现、文件与工具连接见[工具使用](https://boluopai.net/getting-started/)；本页集中介绍较复杂的科研与学习安排。

## 1. 从问题选择能力

| 你想推进什么 | 可以组合的能力 | 应当看到的结果 |
| --- | --- | --- |
| 弄懂概念、论文或跨学科问题 | 老师方法、学科专家参考、原始教材与论文、概念图和演示 | 有根据的解释、关键区别、可回查的原文，以及针对疑问的进一步展开。 |
| 找到并比较有关研究 | 搜索与论文检索、文献综述、题录和引用管理 | 相关文献、取得的全文与版本、比较结论，以及尚未取得或不能确定的部分。 |
| 把直觉发展成研究问题 | 学科参考、假设生成、批判性思考、研究设计与方法比较 | 清楚的问题、竞争解释、需要的观察，以及什么结果能够区分它们。 |
| 建立或检验一个模型 | 形式化方法、符号计算、图、仿真、统计、机器学习和可视化 | 假设明确的模型、可运行的计算、结果与适用范围；必要时比较不同模型。 |
| 写成论文、报告或可分享的讲解 | 学术写作、引用核验、图表、排版、审阅与修订 | 可维护源稿、可读成品、可追溯的图表与引用，以及尚未解决的问题。 |

同一个任务可以往返这些活动。读到新证据可能改变问题，计算可能暴露假设不足，写作也可能发现概念混淆。先处理当前真正卡住的关系，再选择对应方法；不把每次工作都变成一条必须走完的研究流水线。

## 2. Scientific Agents 与 Scientific Agent Skills 怎样一起用

这两个项目名称相近，贡献有所不同。[K-Dense Scientific Agents](https://github.com/K-Dense-AI/scientific-agents)提供按学科和专业组织的专家思考参考，帮助模型注意一个领域的重要问题、概念、假设、判断方式与常见错误。[Scientific Agent Skills](https://github.com/K-Dense-AI/scientific-agent-skills)提供更具体的研究能力包，例如文献检索、实验设计、统计分析、机器学习、科学计算和图表制作；包里还可能带脚本、例子与接口说明。

可以把前者理解成「从哪些专业角度把问题看清」，后者理解成「用哪些具体方法把工作展开」。这种区分不是硬边界：专家参考也会讨论工具，具体方法也包含推理。两者都需要结合当前来源和实际结果判断，名称不会让模型自动成为合格的人类专家。

例如，想研究一个随时间变化的过程，可以先组合相关领域、动力系统与统计学参考，辨认状态、观测、时间尺度和可比较的解释；再按数据与问题选择图分析、状态空间模型、仿真或统计方法。如果现在只想理解「反馈与相关有什么区别」，老师可以借用同一批参考讲解并制作一个例子，不必先建立完整实验。

**这周的实际改进，是把整套学科参考与选定的具体方法接到可以主动发现的入口。**截至 2026-10-24，示例环境已保留 Scientific Agents 的完整 503 份学科参考，并在研究工作区提供 63 个选定 Skill，包含其他来源与自制方法。中文的「学科与研究方法库」把相关资料接到本地和 Web 老师；模型可以按问题找到索引、读取合适的原文，再组合方法。数字描述这个日期的可用材料，后续以实际目录为准。

完整保存参考库，方便以后查找；当前任务仍只读取有用部分。专家资料是可借用的思考资源，不要求同时启动数百个子智能体。方法包已存在，也不表示其中每种软件、模型权重、GPU 环境和外部账号都已安装。执行时由模型检查当前项目需要什么，再准备实际依赖。

可以直接这样提出任务：

> 帮我从相关学科角度理解这个问题，比较几种合适的方法。先讲清它们各自在回答什么，再用现有工具做需要的分析；不要让我先选 Skill 名称。

## 3. 让文献成为可使用的证据

资料工作包括发现、取得、核对、比较和接回问题。搜索工具适合寻找线索；论文检索与题录工具帮助定位作者、标题、年份、DOI 和版本；全文阅读才使模型能够检查论证、方法与结果。摘要、综述和原始研究可以一起使用，但各自能支持的判断不同。

可以让模型完成一个连贯的资料包：围绕问题检索，复用已有材料，去重并核对题录，取得实际可用的全文，再整理一张比较表。表格写清每篇研究处理的对象、资料、方法、主要结果、限制，以及与你的问题有什么关系。下载没有成功时，留下具体缺口；预印本与正式发表版本不同，保留版本对应。书、论文、补充材料、代码和数据的入口相互连接，后来修改判断时能回到原件。

批量研究时，可以选用 `paper-lookup`、`literature-review`、`citation-management` 等方法，与通用搜索、论文检索及已有文献库配合。使用哪项服务取决于当前覆盖和实际可达性；一次成功的查询只说明那条路径可用。引用管理器可以帮助工作，已有文件与 BibTeX 能满足需要时，也可以直接维护，不必先新增一套服务。

需要长期跟进时，把论文与书籍采集、工具发现和已选方法的更新区分开。前者丰富研究材料，后者寻找新的能力，更新则维护已经采用的来源。按问题设定合适的节奏，记录新内容相对已有材料的贡献，把值得使用的全文、代码和方法放回原有库。时间表已保存与任务实际完成，应当分别检查。

## 4. 从研究构想到计算、数据与图示

先让模型说明研究对象、观察到的材料、为了计算采用的表示，以及希望判断什么。符号推理、统计估计、机器学习和仿真可以合作，但支持不同的结论：推导说明假设下的后果，统计分析刻画资料中的关系，预测需要在适合的保留数据上检验，模拟展示所设规则如何演化。把它们接起来，仍要解释模型与现实对象如何对应。

| 所需工作 | 可选方法与工具示例 |
| --- | --- |
| 公式、关系、事件与图 | SymPy 做符号计算，NetworkX 处理图，SimPy 支持离散事件模拟；具体表示由问题决定。 |
| 统计与不确定性 | statsmodels 提供常用统计模型；PyMC、PyTensor 与 ArviZ 可组合概率建模、计算和诊断。 |
| 时间变化与机器学习 | 按资料选择时间序列、scikit-learn、解释方法，或确有需要的深度学习与图学习工具。 |
| 数据整理与检查 | 检查缺失、重复、测量单位、时间、个体与分组，再选适合规模的数据处理方法。 |
| 研究图与理解用图 | 标准绘图工具制作带轴、单位和不确定性的研究图；概念图、流程图或交互演示帮助理解结构与条件。 |

这些是已选方法库中的入口，不是一张同时安装的清单。模型可以先做一个能回答当前问题的计算，再根据结果扩大范围。需要验证程序接线时使用合成数据；要支持关于现实的结论，还需要对应的实际资料与研究设计。一个脚本运行成功，并没有同时验证科学解释。

图示也应承担明确工作。比较方法时，让假设、输入和输出相邻；解释动力过程时，可以改变条件、观察轨迹；交付研究结果时，保留数据、代码与可导出的图，不用生成式插画代替定量图表。交互工具帮助形成直觉，正式图表帮助检查与传播结果，两者可以来自同一份分析。

## 5. 从源稿到可阅读、可修订的交付物

把研究问题、论证、分析和引用组织成可维护的源稿，让模型承担成文、重写、格式和技术细节。你可以从口述、已有笔记、对某处不满意或一份待修稿开始，不必先交出完整初稿。模型应解释关键论证和修改理由，让你能判断它是否表达了自己的目的。

在示例工作区中，Markdown 与 LaTeX 是主要源稿形式，PDF 是常用阅读与提交成品。公式、证明或期刊模板适合 LaTeX 时采用它；需要接收协作者 Word 文件或刊物明确要求 Word 时，再使用对应文档工具。软件和格式服务于当前成果，不让上游 Skill 的默认输出决定每个项目。

可组合学术写作、引用管理、科学图表、期刊格式、审阅、回复审稿意见等方法。每次交付核对引用是否确有其文、论断是否获得来源支持、图表是否对应当前结果，以及导出的页面是否清楚。保留可编辑源和有版本标识的成品；后来修改一个计算或定义时，能找到受影响的图、正文和引用。

投稿建议、准备投稿材料、实际提交和对外发送是不同动作。模型按照这项任务已有的授权把工作做到对应边界，并把成果、依据和仍待判断的事项讲清楚。写出流畅的论文不等于研究结论成立。

## 6. 老师把专业方法变成可以进入的问题

学科参考帮助老师看见问题的结构，具体方法提供例子和可运行演示；老师仍负责你正在学什么、已有理解、讲解方式与对话接续。你可以说「我不懂这里为什么这样定义」「用图讲一下」「它与我前面的想法有什么关系」，模型从相关原文和方法展开。研究资源能够服务学习，学习也不必每次产出一个研究项目。

**持续学习需要能独立阅读、又能随对话修改的材料。**示例 Teacher 方法按对象组织：哲学与文本研读通常是「术语表＋论述与研究指南」；技术课程通常是「术语表＋学习与研究指南＋习题与实验」。术语表从概念地图与主线进入，主文连贯地展开问题、理由、条件和区别；训练按实际材料准备，已有训练不意味着当场必须做完。孤立问题可以直接讲解，不必先生成整套文件。

哲学和思想史要保留论证、语境、异议与概念变化；技术学习把概念、数学关系、代码行为与实际条件连起来。材料应在相关论证处联系读者的问题、已有理解、兴趣与生活或研究经验，说明哪些关系能迁移，哪些条件不同。不要只在开头加一句「这与你有关」，也不必为每种联系另造一份文档。原文主张、模型类比与个人经验仍须分清。

**模型写出解释，与你能够理解，是两个需要接上的结果。**保存的指南保留结构与来源；当前讲解根据疑问、直觉、异议和反馈调整深度、例子与入口，再把有用理解写回。需要练习时，让你有机会自己判断与修正；需要成品时，模型也可以直接承担推导、代码与整理。不要把记住全部术语或亲手完成每个细节设成理解的前提。

阅读入口可以很具体：在 Obsidian 中把原始 PDF、术语表、指南和适用练习相互链接，用[反向链接](https://obsidian.md/help/plugins/backlinks)、[指定页 PDF 嵌入](https://obsidian.md/help/embeds)和[分栏](https://obsidian.md/help/tabs)往返解释与原文；视频材料保留时间戳和讲话文本，需要声音信息时回到音频。处理一组固定来源时，也可以用 [NotebookLM／Gemini Notebook](https://support.google.com/gemininotebook/answer/16179559)提问并核对引用。图像、声音和交互演示按其对当前理解的贡献选择。

先使材料易读、可比较、能回到来源。只有实际检索或接续困难时，再增加分类、标签或知识库。工具承担记忆、检索与排版，读者保有阅读、辨认、提问、尝试和反馈的空间。

## 7. 让工作区和能力介绍一起保持可用

**工具库、研究项目、原始资料和交付物，各有稳定位置。**示例环境将通用研究工具放在一个工作区，每个具体研究有自己的仓库、代码、依赖和实验；原始书籍论文留在资料库，便于阅读的交付版本进入文稿空间，并注明来源版本。已有稿件不必为了这种安排全部搬家。模型负责找对位置、维护连接和处理版本，你不用记住每个目录。

一份可读的当前说明，应让人能够回答：这里有哪些能力，什么时候会用到，从哪里提出任务，会得到什么，哪些方法还只是可选参考。模型维护的技术入口则进一步指出实际源、依赖与执行方式。两者连接到同一份工作；不能因为模型会搜索配置，就省掉给人看的介绍。

这周的环境改进把学科资料、具体研究方法、本地与 Web 教学入口，以及按项目发现的能力接在了一起；选定来源也进入既有的每周维护。更新时比较实际内容与本地适配，验证受影响的方法，把变化写回介绍。用不到的依赖不必预先安装，已经禁用的能力也不因更新被擅自开启。看到目录中的一个名字时，应能进一步确认它是可读参考、可调用方法，还是已经运行过的工具。

可以让模型定期回看相关 History、项目提交和实际产出，检查新能力是否已经落地、旧说明是否过时、曾经可用的入口是否还能继续。历史摘要帮助定位，原文件和实际运行负责核验。把真正有用的改进整理成人能读懂的介绍，而不把全部日志复制到页面上。

回到[工具使用](https://boluopai.net/getting-started/)查看通用环境安排，或把当前研究与学习问题交给模型，从这里选一组有用的能力开始。
