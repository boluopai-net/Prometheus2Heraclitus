# 共享 Skill 与个人哲学

[首页](../../README.zh-CN.md) · [阴阳方法](../../SKILL.zh-CN.md) · [English](skill-package.md)

本说明维护这套阴阳实现的文件与更新约定。集合名为 **Prometheus2Heraclitus**，
其中完整的阴阳成员位于 `skills/yinyang/`。`references/docs/` 与
`references/diagrams/` 是配套资源，不是独立 Skills。
从公开仓库取得完整目录，通过实际使用环境的 Skill 机制提供给模型。
网站提供阅读；克隆仓库和 GitHub 原生 ZIP 保留完整源内容。

阴阳是一项已经展开的哲学与形成方法。读者可以采用、组合选定资源，也可以创作不同作品。
[从采用、组合到自己的创作](example-and-commons.zh-CN.md)展开这份邀请。
哲学家的思想可以支持框架，不能替代实际用户的描述。本说明的五份描述与公共更新约定
适用于完整采用持续维护的 Skill；阅读哲学或取用某项方法，本身不等于采用这份约定，
也不要求开展个人哲学项目。

## 公共内容与情境化内容

分发副本与个人副本保持字节一致的公共内容。永久写作指引位于 `references/formation/`，
附有完整中文版本。私人情境化版本增加以下固定五份描述；公开分发不包含这些文件，也不
包含占位描述。

| 固定情境槽位 | 职责 |
| --- | --- |
| `references/situated/orientation.md` | 采纳的哲学、价值与方向。 |
| `references/situated/person.md` | 对实际个人有根据的理解。 |
| `references/situated/counterpart.md` | 实际模型与期望贡献。 |
| `references/situated/relationship.md` | 共同活动、纠正与分工。 |
| `references/situated/environment.md` | 通过实际环境实现。 |

人、伙伴与关系仍是三个建模对象；取向提供采纳的解释与评价方向，环境说明实现。
这五份不全是心理模型。[形成方法](../design-and-revision.zh-CN.md)把每份描述接到永久
指引，采用后仍然保留。

公共的[修订指南](../revision-guide.zh-CN.md)是与五份描述并列的第六个工作文件，
说明 personal 支持材料、个人模型、Skill 与环境怎样相连地更新，也说明网页预览与
发布的顺序。它属于公共包，有完整中英文版本，不增加第六份私人画像。
入口将它纳入初始阅读，让使用模型理解怎样维护正在使用的安排。

采用时，根据相关且获授权的材料形成全部五份描述，整理必要私人支撑。
模型承担写作，用户不必亲自维护文件。明确的未知可以是真实的情境化内容；
未改写模板、复制画像和虚构人物不构成已形成的个人版。
检查融贯、根据、可取得的证据，以及实际对话模型能否在使用入口读取并使用这些描述。
后续修订只需改变受影响内容。

`references/personal/sources.md` 是实际私人证据入口，支持五份描述，不成为另一份核心。
公开[证据指引](../formation/sources.zh-CN.md)提供方法。进一步的 `references/personal/`
材料保留有用的私人支撑与专题出处。文件名跟随实际证据，
没有普遍文件清单，也不要求为每篇文章建立空白对应页。原件和较长历史可留在既有维护位置，
通过有访问边界的引用取得。哲学正文只维护一份：私人对应页链接公共论证并保存私人依据，
不复制第二套理论。

整个 `references/situated/` 和 `references/personal/` 之外的一切都是公共内容：主入口、读者版、方法、
文章、图示、阅读地图、管理文件、脚本与 OpenAI YAML 适配文件。共享 GitHub 包维护这些内容。
[主入口](../../SKILL.md)维护初始阅读，另有[中文阅读版](../../SKILL.zh-CN.md)；
[形成与修订](../design-and-revision.zh-CN.md)维护形成，
[环境适配](../harness-adaptation.zh-CN.md)维护实际实现。

## 投影公共变更

`scripts/sync-common.py` 默认检查公共源内容的投影。`--apply` 把公共文件投影到目标，
保留两个私人目录中的一切，包括额外文件与链接，不遍历或检查其内容。它不推断一个人、不导出私人文件，
也不发布到运行环境。

新的个人版从完整共享副本开始，再形成私人描述。用明确包目录比较：

```bash
python3 /path/to/shared/yinyang/scripts/sync-common.py \
  --source /path/to/shared/yinyang --target /path/to/situated/yinyang
```

加上 `--apply` 复制变化，再运行比较。目标中未对应文件和公共路径符号链接会阻止复制；
检查归属，不静默删除。既有本地或私人 Web 维护者安装和发布投影源，再回读实际使用处。

旧包在 `references/{encounter,models,relationship,usage,sources}.md` 混合公开指引与私人
内容。任一包仍有这些路径时，投影器在改变文件前拒绝操作。维护者先按实际含义分配到五份
新描述与私人证据索引，保存独有支撑，再退役旧路径。旧相遇可能同时包含取向与关系，旧关系
可能同时包含伙伴与共同活动；机械改名不能完成这种语义迁移。私人
`references/personal/README.md` 中有用的内容保留在适当维护者处；整个私人目录受保护。

公共内容的一致性保留一项接收方本地的发现标记例外：若目标 `SKILL.md` 的单行
`description` 已以「用户自制：」开头，投影时保留这个前缀，并用公共源替换其余描述；
没有该标记的目标不会被加上。其他公共字节与文件模式仍由源维护；公开包不会把自己
标为接收方自制。

字节一致适用于选择持续采用公共更新的副本。独立替换哲学或组织时，在自己的来源处保留
作品并维护连贯引用；即使仍采用五槽位格式，也不要用本公共包覆盖它。

另行创作可以改变描述的数目、组织与哲学；当前维护的阴阳实现保持这固定五份。

## 私人与公开边界

个人描述即使经过形式化或面向模型书写，也仍属于私人内容。私人引文、传记、心理和
健康记录、关系叙述、账户信息、私人路径、对话标识和未发表手稿留在实际维护位置。
一般化抽象不授权公开能够重建私人来源的链接。

只有获授权的可复用认识回到集合。阴阳原创材料采用 CC BY-NC-SA 4.0，
其他独立成员保留各自 MIT 许可。权限、署名与来源审查遵循
[集合说明](https://github.com/boluopai-net/Prometheus2Heraclitus/blob/main/README.zh-CN.md)及实际发布维护者。私人改编不必公开。
