# Use in the actual environment

This public copy explains how to write the situated use account: how this
person and counterpart actually enter, continue, and complete work through
their available environment. It connects the [user model](models.md) and
[relationship](relationship.md) to resources and actions. A tool inventory
would say what exists; this account explains what a resource enables, when it
matters, and how the participants take up its result.

For full adoption, give this file grounded substance alongside the other four
situated accounts. Initial reading remains with the [entrypoint](../SKILL.md).
A reader borrowing a method can apply the relevant connection within an
existing workflow without adopting the complete package.

## Give the relation a reachable working form

Start with activities the participants actually undertake and the points where
a contribution depends on a resource, channel, or action route. A person may
express an unfinished idea in speech; the counterpart may receive a transcript,
recover relevant work, inspect sources, and write or implement the result.
Explain the passage between these contributions. If only text is available,
the counterpart can interpret that text but cannot claim to have heard vocal
features it did not receive.

Write from current evidence about the environment. Identify the actual owner
or locator of relevant materials and what the present counterpart can access.
A reader-visible file is not automatically a model-readable source; a named
service is not automatically callable. Where the current interface can only
advise, explain how its contribution reaches the execution owner. Where it can
act, connect the route to the intended result and its observable readback.
Capabilities and authorization follow their actual owners.

Choose the routes that make ordinary work possible. For a learning activity,
this might mean finding the selected text, preparing a useful explanation or
diagram, and returning to the disputed passage when understanding changes.
For implementation, it may mean recovering the current project, developing
the intended behavior, editing at its source, and checking the result where
it will be used. Domain Skills own their methods; link the relevant entrance
instead of reproducing a workflow here. Record a local dependency only when
the activity actually depends on it.

## Locate the contribution that is missing

Understanding, retrieval, beginning, responding, stopping, and switching are
different practical achievements. An explanation may make a relation clear
while leaving the next action inaccessible. A useful account shows how the
environment supports the particular passage at issue.

Consider a fictional collaboration returning to an unfinished essay. A saved
note can preserve the question and alternatives, yet leave both participants
reconstructing which draft is current and what remains to do. A useful route
would connect that note to the maintained draft and the unresolved passage so
the counterpart can carry the next authorized work. It might prepare an
editable opening or examine a disputed source. Which contribution fits depends
on the purpose and what actually prevented continuation. Requiring the person
to design and supervise an elaborate recovery process could recreate that
burden.

Assess the costs of the whole arrangement. A tool can save an operation while
adding setup, monitoring, handoff repair, or repeated context reconstruction.
A record preserves something; retrieving it makes it available; carrying the
action changes the work. Relief concerns the person's experience, while
learning concerns what they can subsequently understand or do. Keep these
outcomes distinguishable when judging whether a route helps. The
[participation and support essay](docs/participation-and-support.md) develops
these connections.

Keep this account selective and current. Link maintained sources, resources,
and specialist methods; keep private locators with their actual private
owners. When access changes or use exposes a gap, determine whether the route,
the allocation of contribution, or its underlying interpretation needs repair.
[Harness adaptation](harness-adaptation.md) owns making and checking those
changes; [design and revision](design-and-revision.md) owns the connected
understanding. Verify that the intended activity can actually continue through
the revised route. A list of available tools or a successful file read alone
does not establish that result.
