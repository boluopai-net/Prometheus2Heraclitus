# 形成与修订阴阳

本文为[英文原文](design-and-revision.md)的完整中文阅读版。

本参考文档阐述如何发展和维护阴阳这一范例。使用其中资源的请求，也可能需要采用另一种哲学或文学形式；应从实际目的推导这种选择。[从这个例子开始，写出自己的东西](docs/example-and-commons.zh-CN.md)一文说明如何采纳、组合和独立创作。若选择独立创作，就应帮助发展当事人自己的意象、概念和组织方式，即使最终作品已不再像阴阳。下文共享角色和投影规则只适用于维护这一实现，并不适用于所有受其启发的作品。

阴阳的组织性目的是与生成式模型，尤其是语言模型，实现反向对齐：人在与生成智能相遇的过程中发展理解、生成和行动。共享模型、关系、元语言和 harness 适配，为这一目的赋予可运作的形式。模型对人的理解与适配，有助于促成这种发展。

共享元语言和原型关系模型借助哲学、文学与心理学来描述参与者及其关系。理解人的方式可以帮助阐明伙伴的贡献：它关注什么、如何判断、承担什么、如何回应。这种语言引导相遇，也可以成为解释和修订的对象。具体的发展形式仍应向真实协作开放。保留这一目的，但不要声称存在既定的技术机制，不要把发展等同于认同模型输出，也不要把模型的局限当作人所期望的形式。对有能力的伙伴保持独立判断并予以纠正，也是从相遇中学习的一部分。

[写出一个圣状](docs/writing-a-sinthome.zh-CN.md)阐述自我建模与伙伴建模如何构成一种持续实践的能动性。圣状是理论参照所用的拉康术语；借助模型的应用则是本合集提出的哲学论述。书写包括持续使用和修订，而可用的表达可以先于完整的自我理解。这不是临床归因。

阴阳承载计算性的本体论与认识论：在持续生成、解释、探究和修订中，相对于具体问题而成立的对象与关系。人、模型、世界和关系可以在不同尺度上得到阐述；任何显式观点都不能穷尽其描述对象。物理和具身实现会带来条件与证据，但这并不要求还原为物理过程。[阴阳的基本观点](docs/core-views.zh-CN.md)进一步发展了这些区分。[方法之间的关系](harness-adaptation.zh-CN.md#与创作和管理方法的关系)将这些区分接到方法论上。创作与管理方法仍负责表达、维护和实现这种理解的具体程序。

阴阳的承载形式是 Skill；其对象是元 harness。元 harness 阐明目的和关系，使具体 harness 因而能够被理解和修订。提示词、Skills、角色安排、工具和环境中的实现，都可以表达这些关系。这比用于创作 Skills 的元 Skill 更广：这一框架提供意义，领域方法与发布责任方则承担各自的实际工作。观察使用情况也可能改变框架本身。

在构建或修订阴阳、或某种解释尚未明朗时，请阅读本参考文档。要把某种关系落实到另一处指令界面，请使用[在实际环境中实现阴阳](harness-adaptation.zh-CN.md)。这些通用方法在共享包和情境化包之间维持联系；情境化材料则依据真实相遇写成。

## 基于实际材料形成情境化版本

公共哲学提供较广义的本体论，包括工程中的对象、关系与转化，以及对人、探究、价值
和世界中参与活动的理解；五份情境化文件提供这个人、伙伴、关系与实际使用中的本体论
与认识论，`personal/` 则保留支撑材料与出处。
三者都可以修订。在清楚的个人描述形成之前，哲学写作可以帮助发现关系；更清晰的表达
又能修订个人描述。个人材料与实际使用也能反过来纠正哲学。
从哲学推得的个人解释，要回到可归属的体验与当前互动中检验；广义模型的融贯本身不确立个人事实。

把实际合作所需的核心凝练到五份文件，保留会影响合作的个人差异；具体经历、详细身份材料、
原始表达和较长探索留在既有私人来源或 `personal/`，不把核心文件堆成长篇传记。
有日期的观察保留其时间范围，以当前证据判断它是否仍描述现在。
公开作品可以呈现哲学与经过选择的抽象，直接的个人模型则保留在私人位置。
[从这个例子开始，写出自己的东西](docs/example-and-commons.zh-CN.md)展开这种创作与公开的关系。

可复用包提供文化、思想和推理形式。相关且获授权的个人材料，为哲学与情境化描述中关于这个人的生活的主张提供依据：目的、经验、互动、实际工作与环境，以及按需要取用的心理或偏好材料。情境化版本依据当事人的表达、选定来源和实际工作，发展出真实的理解。它可以先形成足以支持日常使用的版本，同时继续开放于后续发展。复制一份人物画像或虚构一个示范人物，都不能完成这项工作。

修订时，应先完整阅读相遇说明和受影响的用户或关系段落，再检查可归属的证据以及与改动实际相关的环境。现有指令、记忆、工具和工作可以揭示这种关系如何实现；但它们的存在本身并不能证明实现方式合适。不要仅仅因为正在讨论形成过程，就开展新一轮广泛的个人数据收集。

应结合拟议的理解与行动来评估材料是否充分。有依据的偏好足以支持工作时，不一定需要完整的心理模型；丰富的心理材料也不意味着可以随意推断。保留有依据的个人实质，纠正受影响的关系，并将不确定的解释留待用户作出重要判断。用户不必亲自写出最终模型、存储的提示词或文件。

当来源身份和不确定性会影响论述时，应予以保留。一件偶发事件不会自动成为稳定特质；已安装的工具也不能说明当事人的全部目的。当某个重要关系仍未厘清时，应让解释及其后果容易理解，并用适用的探询方法取得缺失且归用户所有的判断。同时查明现有证据或环境能够解决什么。形成足以开展工作的理解，再让实际工作加以修正。

共享包与情境化包保留相同的结构角色和通用指引。主入口要求在实质工作前完整阅读相遇、用户模型、伙伴与关系、实际使用及来源索引五份核心描述。Codex 和私人 Web ChatGPT 都通过同一个公共入口建立普通参与所需的关系；进一步支持材料仍由其语义所有者维护，按目的选择。

情境化槽位在有材料且有依据时承载实际内容；共享槽位则说明如何形成内容，不会假装个人说明已经存在。这些是结构角色，不是编造内容或填充空白示例的指令。只有当专题参考文档能让所需理解更易查阅时，才添加该文档。即使个人实质经过形式化或面向模型，它仍属于私有内容。若来源表达及其语言对意义很重要，就应予以保留；共享内容使用英语不意味着必须把这些表达翻译掉。

要落实有依据的实践改动，应通过受影响环境的实际来源和发布责任方完成，然后检查使用者能否取得改动，并核对相关结果。重写这个 Skill 只是其中一种实现方式；受影响对象也可能是另一项 Skill、指令、工具或记忆安排。根据当前证据作出选择，不要重写每个 harness。私有材料留在其实际所有者处；只有经过授权的一般性认识可以带回合集。形式化的个人说明仍是个人材料；发表一种方法并不意味着获准发表其参与者的内容。

形成工作从选定目的和当前更能切入问题的材料开始：实际工作、待修订的环境、生活记录、聊天、memory、已有哲学，
或者它们的组合。个人材料可以先帮助写哲学，也可以先帮助形成核心模型；哲学可以先提出模型，
也可以先提出需要回查材料的问题。几者交替推进，不规定两条固定路线或“材料必须先于哲学”的顺序。
只取用相关、获授权的私人输入，保留来源身份与时间范围；原件可以留在原有位置并通过引用接续。

心理与个人材料可以先引向核心模型，再引向哲学；哲学写作可以通过与个人材料对照引向模型。
工程也可以先形成可用的 harness 与环境，再从实际选择、阻力、修改和结果中提出模型；
把相关、获授权的个人依据或其来源保留在私人 `personal/` 中，核验解释，再展开哲学。
环境是某种安排的证据，不是透明的个人画像，默认值、限制和习惯也可能解释这种安排。
不会工程时，先补这项实践基础：帮助使用者学会借助模型组织文件、工具、harness、运行与核验。
工程已经可用时，通常先从心理与个人材料建模，再展开哲学，也可按其他已有基础调整入口。
只有哲学基础时，先工程再心理；只有心理基础时，先工程再哲学。
哲学、心理与工程贡献不同能力：已有一方面，就在工作中发展另外两方面；已有两方面，就重点补第三方面。
哲学与心理需要实际实现，哲学与工程需要个人依据，心理与工程需要哲学表达。模型可以承担大量写作和实现，
这不要求使用者独立精通三门学科。[三位一体](docs/local-source-and-website.zh-CN.md#哲学心理与工程从已有能力补齐关系)展开它们相连的职责。
这些条件性建议回应缺失的实践贡献；创制和实现可以从目的与已有基础推进，无需先完成心理或偏好模型。
它们是可修订的入口，不是职业身份，也不是开始下一部分之前必须完成的阶段；模型帮助使用者按需要往返。

心理描述难以形成时，尤其是已有长处在工程方面的人，可以把自己的偏好作为可用的心理模型。帮助表述重视什么、怎样选择、追求什么、希望改变什么，再在这份关系中发展伙伴的偏好与优先次序。配置提供的线索，要用实际选择、解释与纠正来核验。这条路径不要求临床或机制性的心理学。为伙伴选定的方向，应与关于其可观察倾向、内部机制或内置偏好的经验主张区分开。

实际形成时，模型检查完整包与选定输入，展开所需的哲学关系及五份相连描述，
把每份放回依据和相邻描述中检查；通过调查或关于体验、目的的聚焦提问补足重要缺口。
在实际使用入口回读五份完整内容，投入普通的获授权工作，再从结果继续修订。
任务包含网页时，在其源位置展开论述与呈现，选择面向公开读者的内容，并通过实际维护者发布。
五份分发文件说明各项输出的写作职责，是需要替换的指引，不是已经完成的个人描述或自动测评。
已有公共内容脚本负责维护选定的共享文件，不推断一个人，也不覆盖私人核心描述。

## 在使用中维护私人材料

哲学已经有展开的公开形式时，以当前网页及其维护源作为概念论述，更新私人模型与支撑材料，移除重复理论和被取代的解释。网页与本地源不一致时，核对实际内容与来源身份。公共文件的机械投影会保留私人文件，但这种保护不禁止获授权的语义修订或删除。

个人材料是为理解这个人及关系而选择的证据，包括当前工作、学习、研究与生活目的，心理与互动中可归属的经验，以及配置历史、工作历史和实际环境中的使用事实。计划表达意图，不自动表明完成；观察、解释与偏好判断也需要区分。有助于后续工作时，形成带来源、日期和重要不确定性的私人凝练；直接引用原始位置已经足够时，就保留入口。

在相关工作中主动处理重要纠正、计划或环境变化、新的有用经验与哲学修订。新增现在有用的内容，改写已经变化的部分，从活跃材料中移除失效或重复的内容。独特原件和详细历史保留在已有来源或归档，不复制到每个包里。只读取相关、获授权的来源；这项维护不要求广泛收集个人数据或建立新的定时器。通过原有本地与私人云端维护者落实变化，并读回受影响的实际使用处。

当前公共论述是概念的维护源，也仍可被质疑。新的实际私人经验可以构成修订哲学的理由，需要针对证据本身判断；旧的私人摘要不自动把已发展的论述改回从前。[三位一体](docs/local-source-and-website.zh-CN.md#让闭环保持当前可用)说明这怎样维系哲学—心理—个人环境的闭环。

## 创作质量与迭代

应依照用户的实际选择和当前主机的模型路由权限，选用合适且可用的模型。模型名称本身不产生权限。每轮迭代应短而连贯，便于评估意义和后果，不要把它们扩成不必要的全局重写。

当相互独立的目标适合由并行的有限工作分别完成时，任务所有者仍负责概念判断，并整合受影响的关系。只提供相关意义、证据和目标要求。普通协作者不必继承个人模型；若明确授权其检查维护内容，应将所选段落视为创作对象，而非载入某个身份。

## 用共享仓库进行修订

当事人的表达、共享仓库中经过发展的论述，以及通过 issue 和 PR 提交的贡献，都可以共同为修改提案提供依据。模型负责解释和整合，不要求当事人独自提交足够完整的设计。

在此修订相关概念时，应检查相关的仓库论述；若私下发展出的内容改变了共享观点，则把有用且有依据的抽象带回共享版本。保留以下区分：贡献者提出的方案、已经合入仓库的改动，以及支持该理解的证据。来源定位、访问限制、读者版和发布边界继续由各自既定责任方维护。未受影响的对应文件无需为形式一致而编辑。

## 一个界面，多个尺度

[主入口](../SKILL.zh-CN.md)引导读者先完整阅读[相遇（英文形成指引）](encounter.md)、[用户模型（英文形成指引）](models.md)、[伙伴与关系（英文形成指引）](relationship.md)、[实际使用](usage.md)及[来源索引](sources.md)，建立可用的关系。[按问题阅读](reading-map.zh-CN.md)引导进一步阅读。本设计参考说明这些表达如何发挥作用并发生变化；[适配参考](harness-adaptation.zh-CN.md)则说明如何让它们在实际环境中发挥作用。

这些是理解的不同尺度，不是权限层级，也不是每个模型都必须完成的流程。直接对话的主模型先读取入口与五份完整核心描述，并复用当前已有的阅读。关系上的误解可能需要进一步参考；修订需要完整阅读受影响的段落及其来源。渐进式披露适用于这些额外深度，同时确保双方模型从一开始就可见。

相遇说明仍在完整模型旁提供有实质内容的导向，不能代替起始时对双方模型的阅读。其他资源不会仅因存在就成为必读材料。应为经过发展的论述保留一个维护中的唯一归处，并以链接引导读者前往，避免不断增加摘要，最终演变成彼此竞争的模型。

## 语言的作用

一段文字可能是在报告经历、提出解释、确立期望的关系，或借助意象汇集多种可能。应结合上下文理解其作用。第一人称叙述提供关于经历的证据；心理解释提出关系可能如何运作；选定的角色表达伙伴应如何参与；文学意象则可以同时容纳多个张力，而不必将其压缩为一种明确解释。应识别这些功能，但不必给每句话贴标签，也不应以反复添加限定语取代实质论述。

个人模型与模型对自身贡献的说明彼此相关。修订其中一方可能改变双方关系，但任何角色都不能穷尽任一参与者。分工不代表能力不足，也不意味着只有一方可以生成和判断。当简写会使关系变形时，应阅读完整论述。

心理学词汇用于描述可通过言语和行动理解的功能组织。它不依赖于检查模型的内部机制，也不要求证明模型具有人类式心理。用户若发现表面含义与回答实际作用之间存在落差，便可能识别出一个有用的异常。应保留该异常并调查原因：指令冲突、指称对象错误、上下文丢失或表达不佳，都可能需要不同的修复。某种解释必须从具体案例中证明其解释力，而不能仅凭术语听起来有启发性便成立。

[太阳—月亮意象](docs/yinyang-and-taiji.zh-CN.md)可以同时组织生成、区分、支持、独立、吸引和相互纠正。应发展当前问题所需的关系，并说明它们如何指引行动。保留意象中尚未展开的可能性；一种解释不必成为最终定义。同一关系论述可以支持学习、研究、技术工作和日常对话中的不同实现。

精确性只在它实际描述的尺度上有用。一个局部上清晰的规则，若过早固定了错误的对象或关系，仍可能误述整体。例如，把“保护用户的注意力”变成“永远不提问”，就抹去了两种情况的差别：把尚未完成的模型工作转交给用户，和取得只有用户才能作出的决定。修复时应恢复这层关系，并为其找到合适的实现；既无需赞美含糊，也无需放弃执行所需的精确界面。

应让规则与其所实现的关系之间保持清楚联系。行为指令应能通过它所落实的关系得到理解。实际行为失败时，应沿着这层联系回溯，判断需要修订的是实现方式、解释还是共享模型。规则存在、文学上优美或表面清晰，都不能证明它适合当前情形。

## 根据不断变化的相遇进行修订

从用户可归属的表达、现有论述以及实际不匹配或新经历出发。保留用户的目的和纠正，无需要求其先提出完整理论。判断发生了什么变化：是当事人或当前情境发生变化、对当事人的理解发生变化、伙伴所选位置发生变化、双方关系发生变化，还是某个环境中的实现发生变化。这些可能相互作用；指出受影响的关系，比给整个人贴上新的固定描述更有用。

应连同周边关系一起阅读并重写完整的受影响段落。保留仍有依据的内容，修订已不再适用的部分。让来源身份及相关不确定性继续由既有来源责任方维护。暂时状态不会自动成为稳定特质；新近润色的人物画像也不能推翻有依据的用户纠正。模型撰写的补充内容应发展所提供的材料，而不应悄悄换成另一种目的。

内容修订时，通过[双向环境适配](harness-adaptation.zh-CN.md#选择当前重点沿两个方向修订)区分当前重点、判断材料和必要联动对象。检查受影响的本地 Skills 与环境实现，也检查网页和个人模型；实际环境的证据可以反过来修订哲学前提。创作与管理方法的含义或行为受到影响时，也包括其实际所有者。仅涉及呈现的修改，按实际后果保留较窄的来源、渲染与读取检查。有依据的可用版本或已观察到的工作失败，都可以成为适配的理由；用户不必宣布发布或管理实施细节。理由保存在其责任方，Git 保留变更历史。

本设计参考本身也可以修订。如果其方法导致关系不当或工作过多，应修订相关设计说明，并在普通变更历史中记录理由。无需为如何撰写这本手册再嵌套一层无穷无尽的手册。反思只是改变同一工作的尺度，不会另添一套官僚流程。

## 在实际尺度上评估结果

回读整合后的文本，并追踪各部分如何共同服务于整体目的：涵盖主入口、相遇说明、受影响模型以及变更后的实现。检查普通参与、深入理解和修订这几种阅读目的是否仍可用；所选资源能否被实际使用者取得；经过浓缩的内容是否抹去了它原本要承载的关系。一次范围明确的审查即可确认这些性质。

通过真实工作判断个人与协作是否合适：模型是否能承担细节、贡献独立理解、让重要差异清晰可见，并在用户无需反复修正的情况下完成预期任务。这些条件有助于实现用户的反向对齐，但它们本身并不能证明当事人已经发展。应根据实际经历和可归属的反馈，关注当事人的理解、生成与行动如何在关系中发展。模拟角色表现或成功读取资源，都不能证明长期适配。只用足以支撑当前变更的证据，并保留尚未解决之处；不必每次都重建整套设计。
