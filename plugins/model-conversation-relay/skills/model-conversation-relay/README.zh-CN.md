# 模型对话接续 · Model Conversation Relay

[English](README.md)

继续一段已经准确绑定的 ChatGPT 咨询会话中的一次交换。保留调用方请求、
另一模型回答及其来源，由调用方判断含义、正确性和任务是否完成。

完整方法见 [SKILL.md](SKILL.md)。例如：继续等待已获接收确认的请求；确认中断前
首次提交的结果；准确提交一次已授权的后续请求；为绑定的回答保存不可变回执。
本方法不创建或选择会话，不改变模型，也不改写交换的任何一方。

## 安装与绑定

通过集合的[Codex 安装说明](https://github.com/boluopai-net/Prometheus2Heraclitus/blob/main/docs/codex.zh-CN.md)
安装 `model-conversation-relay@boluopai`，或从
[GitHub 源码](https://github.com/boluopai-net/Prometheus2Heraclitus/tree/main/skills/model-conversation-relay)
取得完整目录，使用客户端支持的 Skill 机制。安装提供方法，不提供账号访问、
消息发送授权、浏览器控制或运行服务。

| 能力或配套方法 | 实际要求 |
| --- | --- |
| 调用方与私人任务存储 | 必需：准确会话、模式和就绪证据，已授权操作，准确请求字节与 SHA-256，既有轮次和尝试证据，以及保存不可变请求、回答和回执的私人位置。调用方保留周围任务与来源依据，并判断回答。 |
| 原生会话适配器 | 条件能力：当前真实暴露的工具及 schema 能够寻址准确目标，并提供足够的有序轮次、运行状态与接收确认。入口中的 Codex App 工具名是示例，不保证每个宿主都有。观察与发送具有不同能力和权限。 |
| [浏览器会话](https://github.com/boluopai-net/Prometheus2Heraclitus/tree/main/skills/browser-relay) | 仅在选择 Browser Relay 路线时必需：安装 `browser-relay@boluopai`，读完入口，绑定接收方配置的受控载体、目标登录账号、目标准确归属与生命周期。它不安装浏览器控制器，也不授予登录访问。 |
| 宿主接续与凭据负责人 | 提供受支持的等待与恢复、真实登录和同意边界，以及安全桌面行为。笔记不等于已安排唤醒；没有受支持的接续方式时，应报告保留的待处理交换。 |
| `cloud-local-workflow` | 宿主已经具备时可选的来源维护方法。它不是公开集合成员，也不是安装前提。没有它时，在调用方已有任务记录中保留任务、来源、模型选择和首次提交证据。 |

把传输回执、真实会话、账号与 Profile 标识以及私人请求放在公开包、插件缓存和
公开仓库之外。所有绑定都由接收方当前宿主解析；本包不提供作者的账号、凭据、
Profile、路径或会话。

## 证据与限制

完整方法冻结目标与请求身份，在变更前确认有序轮次，只保留一次在途尝试；
发送已获接收确认后，即使远端轮次尚未显示，也继续视为待处理。目标空闲或观察
延迟不能成为重发理由。明确未接收，或可观察的终止且不完整回答，只能支持入口
允许的准确重试。中断恢复保留接收确认与重试历史，不重置它们。

完成的传输回执把观察到的回答与其请求和目标准确关联；它不证明回答正确、
证据充分或任务完成。评价或转交时，保留原始回答。

包检查、发现检查与离线确认场景可以核实交付并检查决策边界，而无需发送消息。
实际登录传输、提供方完成信号与接续，仍需在接收方真实获授权的交换中核实。
安装、编写或测试本 Skill 本身不授予发送测试咨询消息的权限。

此公开改写保留本地交换、确认、等待、重试、来源和回执方法，改由接收方解析
宿主绑定，来源配套方法保持可选。原创包材料采用 [MIT 许可](LICENSE)，
