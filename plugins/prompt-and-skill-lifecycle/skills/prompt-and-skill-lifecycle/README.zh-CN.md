# 提示词与技能生命周期

这个可复用 Skill 将指令设计、语义归属、交付和使用证据连接起来。它帮助编写、
审查、组织、发布和维护 Prompt 与 Skill 包，同时看清文本的意义及其实际消费者。

核心运动是 **精神 → 关系形式 → 对象化**：澄清希望形成的关系，展开参与者及其
边界，再通过指令和接口赋予它可工作的形体。决定如何修订时，也从实际行为反向
阅读这三个层次。文学或哲学意象可以承载方向，但不要求采用特定意象或世界观。

## 使用方式

保持整个目录完整。通过当前宿主有文档支持的 Skill 安装或发现机制暴露
[SKILL.md](SKILL.md)，并验证消费者能读取入口及其引用的资源。检出仓库或下载 ZIP
本身并不等于安装。没有原生 Skill 机制的宿主，可以在自身指令层级内将入口和
选定资源作为任务指导来阅读。本包不包含安装器、服务，也不要求特定工具 API。

典型请求包括：“审查这个项目的指令是否存在语义归属冲突”“为另一个消费者改写
这个 Skill”或“检查已发布的包是否真正可用并被使用”。从入口开始，它会按当前
工作指向语义编写、整合修改、交付或使用证据；只阅读当前动作需要的部分。

## 范围与适配

这套方法无需原作者的电脑、仓库、私人文档、模型选择或发布服务。按实际宿主
适配发现信息和交付方式，保留其现有权限、身份验证、同意及停止边界。本 Skill
不会增加强制审批或 Plan 流程。阴阳是可选的相关示例，不是依赖。

公开版保留了实质性的语义方法、单一归属、整合修订、适度证据和消费者回读。
原来的宿主配置及同步脚本，被改写为对实际归属和交付方式的可迁移判断；私人
参与者模型和固定会话基础设施不在包内。两篇外部编写文章在
[编写来源](references/authoring-sources.md)中注明出处，而没有全文复制进来；涉及
当前模型的事实仍需另行核实。

包结构和链接检查只能证明源文件就绪。安装及效果需要在实际消费者中验证。
区分发现、读取、应用与结果，不将其中任何一个当作其余几个的证明。
